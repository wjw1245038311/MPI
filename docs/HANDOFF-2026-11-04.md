# MPI 交接记录（2026-11-04 · 文件/媒体发送链路，已解决）

> 这份文档记录 2026-11-04 那一轮排查的**最终结论**（原稿是「唯一未完成」的交接单，
> 现在已完成并真机验证，保留下来当复盘用）。改动已并入 v0.14.1，安卓侧需要 0.5.157+。

## 一句话结论

「桌面发文件/媒体，手机端看不到或要切走再切回」这条链路共 **5 个独立故障**，全部已修：

| # | 故障 | 根因 | 修在哪 |
|---|---|---|---|
| 1 | 附件入库后手机端不自动出卡 | 主机推的「去刷新」信号写成 `kind:"agent.event"`，而两端客户端是拿 `payload.kind` switch **pi 事件类型** → 整帧被静默忽略 | `attach-file-core.ts` 的 `attachBackfillEvent()`（`kind:"message_start"` + video 占位块，兼容未升级的客户端） |
| 2 | 快照里查不到附件（`hit=0`） | 扩展用的是**桥启动时**的 `MPI_ATTACH_SESSION_FILE`，桥跨会话复用 → 附件记到别的会话名下 | `mpi-attach-file-ext.ts` 改用 `ctx.sessionManager.getSessionFile()`，env 只作兜底 |
| 3 | agent 递的 mp4/mp3/png 只有「下载卡」 | 无差别生成 `file` 块（图片/视频/音频没走各自的块类型） | `chat-attachment-refs.ts` 的 `attachBlockPlan()`：video/audio/image/file 按 mime 分发；图片在入库时生成 1280px 缩略图（`attach-file-thumbs.ts`） |
| 4 | 桌面端一张卡都没有 | 桌面渲染的是**事件流/历史条目**（没有快照那条路），从没解析过工具回执里的 `{"mpi_attachment":…}` | `Chat.tsx` 的 `AgentToolAttachCards`（图片内联、音视频内联播放、文件卡点开预览；机器 JSON 行不再外露） |
| 5 | 回合进行中到的卡不显示，切走再切回才出现 | **客户端**：回合中途补拉快照后，`message_end` 又追加一条**同 id** 气泡 → `LazyColumn` 的 key 重复 → 那段不渲染 | 安卓 `ThreadSession.handleMessageEnd` 改成「同 id 合并」（正文取流式、附件块取快照）；**需 0.5.157+** |

顺带修：附件 GC 的 live-set 只认 `<file … attach="…"/>`，`mpi_attachment` 的对象名不在里面
→ 附件区超 1GB 会被当垃圾删掉（`attachment-gc.ts` 的 `attachMetaNames`）。

## 排查方法（值得复用）

1. **先看主机日志的时间线，别猜客户端。** 三行就能定位层级：
   - `attach-file stored … key=… remoteThread=…` —— 台账键 / 会话映射对不对；
   - `attach-file backfill-ping … subs=N` —— 信号推给了谁、有没有人订阅；
   - `remote-req resync` / `attach-block … hit=N` —— 客户端有没有补拉、快照里有没有块。
2. **`kind` 的取值是 pi 事件类型**（`remotePublish` 里就是 `String(piEvent.type)`）。写错不会报错，
   只会静默落进客户端的 `default` 分支——所以形状必须钉进单测（`test-attach-file` 4d 组）。
3. **「切走再切回就好」几乎一定是客户端状态问题**，不是数据问题：那次的现象正是快照落地 + 流式气泡
   同 id 重复。复现方式写成了安卓单测（先红后绿）。
