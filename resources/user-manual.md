## 1. 认识 MPI

MPI 是 [Pi coding agent](https://github.com/earendil-works/pi) 的独立桌面客户端。项目、会话、模型配置、扩展、权限控制、定时任务、待办任务和文件预览都整合在同一个桌面工作区里。

几个常用概念：

| 概念            | 说明                                                                                  |
| --------------- | ------------------------------------------------------------------------------------- |
| 项目            | 一个本地文件夹。Pi 在这个目录内读取代码、创建文件并执行操作。                         |
| 会话（Session） | 一次与智能体的连续对话，对应一个会话文件。同一项目下可以有多个会话。                  |
| 权限模式        | 控制 Pi 可以自动执行哪些操作的档位：只读 / 严格 / 沙盒 / 完全。                       |
| 扩展功能        | pi 的技能（skill）、扩展包（npm/git/本地）和 MCP 服务器，统一在「扩展功能」面板管理。 |

MPI 和终端 pi 共享同一个 agent 配置目录 `~/.pi/agent`：模型、API Key、扩展、技能、MCP 配置两边通用，在一边装的扩展另一边直接可用。会话文件也存放在这个目录下，所以终端和桌面端能看到同一批会话历史。

每个安装包都内置了固定版本的 Node.js + Pi 运行时（`MPI-Runtime-*.tar.gz`），不需要单独安装 Node.js。首次启动时 MPI 会校验并把内置运行时解压到用户数据目录；之后的应用更新直接复用已解压的运行时，不会重新下载。

## 2. 安装与首次启动

### 2.1 安装包

| 平台                   | 文件                      | 说明                      |
| ---------------------- | ------------------------- | ------------------------- |
| Windows x64            | `MPI-Setup-<version>.exe` | NSIS 安装程序，双击运行。 |
| macOS（Apple Silicon） | `MPI-<version>-arm64.dmg` | 拖拽安装。                |

当前安装包还没有代码签名，首次运行时系统可能弹出安全提示。这是正常现象，确认来源可信后继续即可。

### 2.2 Windows 安装步骤

1. 双击 `MPI-Setup-x.y.z.exe` 启动安装向导。
2. 如果 SmartScreen 提示「Windows 已保护你的电脑」，点**更多信息 → 仍要运行**。
3. 按向导提示完成安装（默认路径即可）。
4. 从桌面快捷方式或开始菜单启动 MPI。

### 2.3 macOS 安装步骤

1. 双击 `MPI-x.y.z-arm64.dmg`，把 MPI 图标拖入「应用程序」文件夹。
2. 首次启动时 Gatekeeper 可能拦截：在「应用程序」里右键点 MPI → **打开**，在弹窗中确认；或者到「系统设置 → 隐私与安全性」里允许一次。

### 2.4 校验安装包（可选）

如果安装包旁附带了同名的 `.exe.sha256` 文件，可以先校验完整性：在 PowerShell 执行 `Get-FileHash .\MPI-Setup-x.y.z.exe -Algorithm SHA256`，把输出和 sidecar 文件内容逐字符比对。应用内也能查看校验步骤：**设置 → 系统与诊断 → 应用更新 → 查看更新日志**（弹窗底部有「安装校验方法」）。

### 2.5 首次启动

1. 启动 MPI。首次启动会解压内置运行时，稍等片刻即可进入主界面。
2. 打开 **设置 → 模型与提供商**，添加你的第一个模型（见[第 4 节](#4-配置模型)）。
3. 在左侧「项目」tab 里点 `+`，打开一个本地文件夹作为项目。
4. 点项目行右侧的 `+`（或 Ctrl+N）开一个会话，发送第一条消息。

### 2.6 开机自启动

**设置 → 系统与诊断 → 开机自启动**。勾选后 MPI 会在登录系统时自动运行（Windows 下在开始菜单的启动文件夹创建快捷方式）。取消勾选即移除。

主窗口分为四个区域：

```
┌────────────────────────────────────────────────────────────┐
│ 标题栏：品牌 · 文件/编辑/视图/帮助 菜单 · 状态文字 · ⚙设置   │
├──────────┬─────────────────────────────────┬───────────────┤
│ 导航栏    │ 会话区（聊天）                    │ 右侧槽          │
│ (左)     │ (中)                            │ (可开关，二选一) │
│ 会话│项目 │ · 顶栏：标题/文件夹/操作按钮      │ · 预览          │
│ │文件    │ · 消息列表 + 工具卡片            │ · 集成终端      │
│          │ · 输入框（附件/命令/权限/模型）   │                 │
└──────────┴─────────────────────────────────┴───────────────┘
```

### 3.1 标题栏

- 左侧菜单：
  - `文件`：新建会话、打开文件夹…
  - `编辑`：复制 / 剪切 / 粘贴 / 删除、进入设置…
  - `视图`：折叠/展开导航栏、切换预览面板
  - `帮助`：使用手册、关于 MPI
- 中间：状态文字（当前会话名 · 模型，或「Pi 已就绪」）。
- 右侧：⚙ 打开设置；最小化 / 最大化 / 关闭窗口。

### 3.2 导航栏（左侧）

从上到下：

1. 顶部按钮行：🔍 全局搜索（等同 Ctrl+K）、折叠导航栏。
2. 快捷入口按钮：「交接新对话」「定时任务」（时钟图标）、「待办任务」（方框对勾图标）和「扩展功能」（插头图标），分别开一段新对话、[定时任务面板](#11-定时任务)、[待办任务面板](#12-待办任务)和[扩展功能面板](#13-扩展功能技能--扩展包--mcp)。「交接新对话」的用法见 [5.2](#52-新建会话与交接新对话)。
3. 三个标签页：`会话` / `项目` / `文件`。
   - **会话**：按时间分组列出**所有项目**的会话（不用先切项目），顶部另有置顶项目宫格与置顶会话圆形印章。
   - **项目**：项目列表，每个项目行有名称、会话数徽标、`+`（在该项目下新建会话）、星形置顶按钮；右键项目可以**上移 / 下移**（仅置顶项）、在资源管理器中打开、置顶/取消置顶项目、归档项目、**更新项目路径**（文件夹被移动后重新指认）。
   - **文件**：当前会话所在项目的文件树，点击任意文件在右侧打开。文件行可以直接拖到输入框作为附件（目录不可拖）。

`+` 按钮（项目 tab 内）打开文件夹：新建或选择项目。

**会话 tab 的三块内容**（自上而下）：

- **置顶项目宫格**：置顶项目排成头像墙（一行 4–5 个），悬停出信息卡，点击直达该项目最近的会话。
- **置顶会话印章**：置顶会话排成圆形印章（一行 6 个，不填色 + 双环描边），悬停出信息卡，点击直达。置顶会话**只在这里出现一次**，下方时间列表不再重复。
- **时间分组列表**：其余会话按活跃时间分组（今天 / 昨天 / 本周 / 更早），行尾显示相对时间（如「3 小时前」），较早的会话自动降噪。

会话行的操作：悬停出现星形置顶 / 归档 / 删除图标；右键菜单按语义分组（移动到上方 / 下方、置顶、克隆、导出、批量操作、在文件夹中打开、删除），每项带图标。置顶项可在置顶区内拖拽换序，也可把条目拖进 / 拖出置顶区。

**「已回收」标记**：长时间没活动的会话进程会被自动停掉以释放内存（默认 2 小时，见「设置 → 系统与诊断」）。这类会话在列表里带「已回收」标记，点开时自动重启，历史完整保留。

**批量操作**：右键任意会话 →「批量操作」进入多选。勾选后可框选（Shift+点击选范围），顶部操作条显示已选计数、「全选」、「归档」、「删除」、「导出」和退出。批量归档直接执行；批量删除会先二次确认；批量导出合成**一个会话包**。置顶印章不参与批量选择。

底部用量行：常驻显示「今日用量 · 总用量」（token 数，k/M 紧凑格式）。悬停查看今日/合计明细、花费与会话总数。流式结束后自动刷新，另外每 60 秒轮询一次；终端 pi 的活动也会计入。

导航栏宽度可以拖动右边缘调整，双击恢复默认。

### 3.3 会话区（中间）

顶栏：

- 左侧：会话标题（**双击即可重命名**，悬停有提示）、工作文件夹路径（悬停显示完整路径，点击在资源管理器中打开；右键可切换工作文件夹）、连接状态提示。
- 右侧按钮（从左到右）：🔍 会话内搜索（Ctrl+F）、⭐ 置顶/取消置顶当前会话、🔀 **交接新对话**（点击＝先生成交接文档再开新会话；长按 600ms 或右键＝原地新建会话）、⌨ **终端**（在右侧槽打开集成终端，见[第 14 节](#14-终端与-pi-tui)）、👁 切换预览。

> 旧版本顶栏的「重命名」和「切换工作文件夹」两个按钮已移除：改名改成双击标题，换文件夹改为右键标题下方那行路径，输入框上方也能切。

消息列表：

- 用户消息在右侧（默认头像「大雄」），智能体回复在左侧（默认头像「哆啦A梦」）；头像可在设置中自定义。
- 工具卡片：Pi 每次调用工具（读文件、执行命令、编辑等）都会生成一张卡片，可展开查看参数与结果。`edit` 类工具的 diff 会自动展开为 git 风格单栏视图（上下文行 + `-`/`+` 着色行），多处替换时标题条显示「N 处替换」徽标；手动收起后不再强制打开。
- 文件产物 chip：Pi 写入或修改的文件会以 chip 形式出现在消息下方，点击在预览区打开。文件多时产物列表**默认折叠**（与工具卡同一交互），不会把对话正文挤下去；展开/收起状态会记住。
- 圆点导航：用户消息 ≥2 条时，聊天区左侧出现竖排圆点，悬停显示该条消息预览（悬停可看到完整输入文本），点击跳转。
- 长任务圆环：输入框左下角。某个工具调用或文件传输跑了超过约 10 秒才出现，环形进度 + 耗时，点开看当前在跑的清单——它**只看当前会话**，不会被其它会话的活动干扰。跑得越久圆环颜色越警示，一眼能看出是“慢”还是“卡”。
- 跳转到最新消息：向上滚动离开底部后，右下角出现圆形双箭头浮动按钮，点击平滑滚回最新。
- 流式输出期间自动贴底跟随；手动上滚阅读时不会被拉回，滚回底部附近恢复跟随，每轮结束后平滑回到最下方。

输入框（Composer），从左到右：

| 控件                | 作用                                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| `+`                 | 添加文件/图片附件                                                                                               |
| `/ 命令`            | 打开斜杠命令菜单（内置命令、扩展命令与技能）                                                                    |
| 任务模式 pill（⚡） | 一键套用「权限 + 思考 + 行为指令」预设（均衡/迭代/调研/审查，可自定义），见 [6.8](#68-任务模式一键切换工作方式) |
| 权限 pill           | 切换当前会话的权限模式（四档，见[第 8 节](#8-权限模式)）                                                        |
| 圆环按钮            | 上下文用量进度环 + 详情浮层（见[第 9 节](#9-上下文管理)）                                                       |
| 模型 pill           | 选择提供商 / 模型 / 思考等级，以及「会话工具」（完成提示音开关）                                                |
| 发送 / 停止         | 发送消息；智能体运行中变为「停止」按钮                                                                          |

输入框上方显示当前工作文件夹（点击可切换项目）。未发送的输入（文本、图片、附件）会按会话自动保存草稿，重启应用后重新打开该会话时恢复。

## 4. 配置模型

MPI 通过 Pi 共享的 `models.json`（位于 `~/.pi/agent`）管理提供商和模型，与终端 pi 完全通用。

### 4.1 添加提供商

**设置 → 模型与提供商**页面分两段：上方是预设供应商，下方是我的供应商。

- 预设快速接入：上段以卡片列出常用平台（阿里云百炼 API 按量付费 / Coding Plan、智谱、DeepSeek、Kimi / Moonshot、Gemini、GPT / OpenAI），另有「自定义配置」「本地部署」两个入口（LM Studio、Ollama 等自托管服务从这里进）。点击平台卡片会打开预填好地址、API 类型和首个模型的新增表单，补上 API Key（按需微调）即可添加。已配置过的平台卡片带绿色描边；如果它还是当前默认提供商，会显示「当前」徽标，此时点击直接展开下段对应供应商的编辑器。顶部搜索框可按名称过滤平台，「刷新预设」重新读取 models.json 更新各平台的配置状态。
- 自定义配置 / 本地部署：打开空白（或预填 Ollama 默认地址）的新增表单，接入任意 API：

| 字段       | 填写说明                                                                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 提供商名称 | 自定义名称，例如 `deepseek`、`openai`、`my-provider`。                                                                                                                     |
| API 类型   | 按服务商文档选择 `openai-completions` / `openai-responses` / `anthropic-messages` / `google-generative-ai`。兼容 OpenAI 的服务通常选 OpenAI 兼容类型，但以服务商文档为准。 |
| API 地址   | Base URL，例如 `https://api.example.com/v1`（注意 `/v1` 路径）。                                                                                                           |
| API Key    | 直接填密钥，或写环境变量引用如 `$MY_API_KEY`。不要把真实密钥写进截图、提交记录或共享文档。                                                                                 |
| 模型 ID    | 服务商真正使用的模型 ID；可留空，稍后在供应商编辑器里补。                                                                                                                  |

填写后点「添加供应商」，再点「保存模型配置」。模型随即出现在输入框的模型选择器中。

- 我的供应商：下段每个已配置的供应商显示为紧凑卡片（名称 + 模型数 + 地址），点击即在下方展开完整编辑器，包括基础地址、API 类型、API Key、请求头、compat 高级 JSON，以及逐模型的设置；重命名或删除供应商也在这里进行。

### 4.2 模型卡片设置

每个模型一张卡片，常用选项：

- 思考：打开后 MPI 会向该模型请求思考档位（关闭则不显示思考等级）。
- 图像：模型支持图片输入时勾选。
- 上下文长度 / 最大输出：按服务商文档填写 token 数；也可以勾「自动」并留空，保存时 MPI 会自动解析（先查 pi runtime 内置模型目录，再探测提供商 API：OpenRouter 系网关 `/models`、LM Studio 原生接口、Ollama），输入旁显示来源徽标（内置目录 / API 探测）；未探测到则回退 Pi 默认 128K。字段已有值时保存不会重新解析；点右侧「↻」可显式重探并覆盖当前值（本地模型改 num_ctx 后用）。
- 测试可用性：一键检查 Base URL、API Key、模型 ID 是否可正常调用。

高级设置（展开卡片右侧）：

- `compat`：仅在服务商有特殊兼容要求时修改，必须保持合法 JSON。
- `thinkingLevelMap`：把 Pi 的标准思考档位逐项映射到服务商档位，不需要手写 JSON。每个档位可选「未指定」（用服务商默认）、「隐藏该档位」或具体标准档位 / 自定义值。

### 4.3 自动模型切换（Auto 模式）

**设置 → 模型与提供商 → 「自动模型」卡**：先配置候选池，从任意供应商添加模型（增删、上下移调整同档平手时的优先级），收费端点勾「收费」；质量档默认自动推断（前沿模型表 → 参数量信号 → 目录价格带），也可以手动覆盖。策略参数同样在这里调整（慢速倍数 / 阈值秒数 / 连续次数 / 恢复探测间隔 / 切换冷却 / 是否允许救急降级 / 切换通知），默认值即可用。

会话级开关：输入框模型下拉顶部有「Auto（自动切换）」项，点击即对该会话开启：

- MPI 按免费优先 → 质量档高到低 → 延迟低到高自动选模型；新空会话开启时立即选定最佳健康候选为初始模型。
- 健康状态从正常对话中采集（首 token 时间 + 错误分类），不产生额外 API 调用；只有需要切换决策时才主动探测候选（最小请求、20s 超时、每模型每小时最多 3 次）。
- 当前模型报错或连续过慢时，自动切到最佳可用候选并弹 toast；处于备用状态时每 5 分钟重探更优候选，恢复且过冷却后自动切回。
- 只切到不低于当前质量的档位；全部低于时可「救急降级」（带警告通知，可设严格模式禁止）。收费模型只在无健康免费候选达标时使用（toast 会注明）。
- 切换只发生在轮次之间，不会打断流式输出。手动选择具体模型等于退出该会话的 auto；非 auto 会话零开销（不监控、不探测）。

pill 上绿点表示 auto 生效中（橙点 = 警告态：用了收费或已降级）；切换后上下文圆环自动按新模型的窗口刷新。

### 4.4 思考等级

Pi 的标准思考档位为 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`（界面显示「关/最低/低/中/高/超高/最高」）。在模型选择弹层里，「思考等级」是一行标签 + 胶囊按钮，点击展开圆角选项列表；若配置了映射，选项会带提示如 `中 → mid`。

注意：实际可选档位还受模型实时能力列表影响。服务商没声明的档位不会出现在当前会话的选择器中。

### 4.5 思考默认值

**设置 → 对话设置 → 默认思考深度**：

- 默认思考深度、默认提供商 / 默认模型：新会话的初始选择（进入会话后仍可随时切换）。
- 隐藏思考块：打开后回复中的思考内容不显示。

### 4.6 配置不生效时排查

1. 打开 **设置 → 系统与诊断**，查看 `models.json`、`settings.json`、`auth.json` 的实际路径，确认改的是对的文件。
2. 常见原因：模型 ID 拼错；Base URL 多/少 `/v1`；API 类型与协议不匹配；Key 无权限；模型没开「思考」所以没有档位。

### 4.7 用户画像（已并入「知芽」）

旧版本的「设置 → 用户画像」页签已移除：画像文本存成了文件 `~/.pi/agent/zhiya/persona.md`，用外部编辑器（Obsidian / VSCode）直接改也生效，新会话即拿到最新内容。

- 注入行为不变：内容仍附加到每个会话的系统提示词里（4KB 截断护栏），AI 从第一条消息起就知道你的背景。
- 入口：侧栏「知芽 Zhiya」→ 人物画像（同一菜单里还有协作约定 / 工作空间 / 知识库 / 当前任务 / 记忆池 / 项目记忆）。
- 旧版填过的画像会自动迁移过来（文件里能看到「迁移自旧『用户画像』设置」小节）。
- 存于 `~/.pi/agent/zhiya/`，不影响终端 pi 的其它设置。

## 5. 项目与会话管理

### 5.1 打开项目

三个入口：导航栏「项目」标题旁的 `+`（选择或新建一个本地文件夹）；空状态页的「打开项目文件夹」按钮；菜单 文件 → 打开文件夹…。选中的文件夹成为当前项目并出现在左侧列表，项目名称旁的数字是该项目下已发现的会话数。

### 5.2 新建会话与「交接新对话」

**普通新建**（开一个空白会话）三个入口，效果相同：导航栏项目 tab 顶部 `+`、某个项目行右侧的 `+`、菜单 文件 → 新建会话。无项目时会先让你选文件夹。

**交接新对话**（聊天顶栏 🔀 按钮）——当前会话聊得太长、想开一段新的但不想它失忆时用它：

1. 点 🔀。MPI 会让**当前会话自己**写一份交接文档（固定结构：目标 / 已完成 / 关键决定 / 下一步）。这一步会实实在在跑一轮模型调用，几秒到一分钟不等。
2. 交接完成后自动开一个新会话，标题就是交接文档的一级标题，首条提示里只让你去读那份文档。
3. 新会话会自动继承旧会话的**任务模式 / 模型 / 思考等级 / 权限**（按这个顺序），所以不用重新配。

需要区分的是同一个按钮的两种用法：

| 操作                | 效果                                                                         |
| ------------------- | ---------------------------------------------------------------------------- |
| 点击                | 走交接：先生成文档，再开新会话。                                             |
| 长按（600ms）或右键 | **原地新建**：直接开一个空白新会话，不生成文档（旧版本的「新建会话」语义）。 |

细节：

- 交接在途时按钮置灰显示「交接进行中…（完成后会自动打开新会话）」，避免连点搞坏正在跑的过程。
- 当前会话还没落盘（从未发过消息的草稿）时，点 🔀 等同于原地新建。
- 交接文档的写作要求写在「交接文档指令」里，可以自己改（「设置 → 对话设置 → 交接文档指令」，见 [17.1](#171-对话设置打开设置默认落在这一栏)）。

尚未发送第一条消息的草稿会话，可以通过右键标题下方那行文件夹路径换到别的项目。

### 5.3 重命名 / 置顶 / 排序

- 重命名：**双击会话标题**（顶栏那个 ✎ 按钮已移除）。
- 置顶：三种等效方式，会话行上的常驻星形按钮、聊天顶栏的 ⭐ 按钮、右键菜单「置顶会话」。新置顶排在置顶区末尾。置顶后的会话在会话 tab 顶部排成圆形印章。
- 排序（仅置顶项）：右键「上移 / 下移」，或在置顶区内直接拖拽；顺序重启后保留。列表区始终按活跃时间自动排序。

### 5.4 分支与克隆

| 操作          | 入口                                | 行为                                                                                                                              |
| ------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 分支（Fork）  | 悬停任意一条用户消息 → 「分支」按钮 | 从该条提问之前分叉出一个新会话，并把被分叉提问的原文自动填入输入框（可修改后发送）。原会话标记为已断开。与 TUI `/fork` 行为一致。 |
| 克隆（Clone） | 侧栏右键会话 → 「克隆会话」         | 把当前活跃分支完整复制成一个新会话文件，包含全部历史。                                                                            |

流式回复进行中点分支/克隆会提示等待结束。

### 5.5 归档与删除

- 归档会话：悬停会话行点归档图标（或右键）。归档后会话从导航栏和默认搜索中消失，可在「设置 → 数据管理 → 归档与回收」或 Ctrl+K（勾选「归档回收」）里找到并一键恢复。
- 归档项目：右键项目 → 「归档项目」。整个项目的会话一起归档，恢复方式相同。
- 删除会话：悬停点垃圾桶图标，或右键「删除」。默认先移入回收站（可恢复），只有从回收站里再删才算永久删除；在「设置 → 数据管理」关闭回收站开关后，删除立即永久生效。详见[第 16 节](#16-归档与回收站)。
- 多个会话一起处理：右键 →「批量操作」，详见 [3.2](#32-导航栏左侧)的「批量操作」。

### 5.6 导出会话包

右键会话 →「导出」，导出的是一个 **zip 会话包**（不是给人读的 Markdown）：

- 里面是会话原始文件（逐字节原样）+ 这条会话用到的附件，保留项目目录结构；
- 换到另一台机器，在「设置 → 数据管理 → 导入会话」里选这个 zip 就能直接导入，会话回到原属项目，附件也不会丢；
- 批量导出把多个会话合成一个包。

几种导出方式对比：

| 方式                         | 产物                | 能不能再导回 MPI     |
| ---------------------------- | ------------------- | -------------------- |
| 右键会话 → 导出              | 单会话 zip          | 能                   |
| 批量操作 → 导出              | 多会话 zip          | 能                   |
| 设置 → 数据管理 → 备份与恢复 | 全量/可选的会话 zip | 能（且可选覆盖策略） |

### 5.7 会话的其它行为

- 原地新建会话（顶栏 🔀 长按或右键、项目行 `+`）：在当前工作上下文中开一段新对话（同一项目）。
- 重启恢复：退出 MPI 前停留在哪个会话，重新打开就自动进入该会话；若该会话已被归档/删除则静默跳过。
- 优雅停机：关闭会话或退出应用时若有进行中的任务，MPI 会先中止并等待落盘（上限数秒），避免损坏会话文件。
- 进程回收：长时间没活动的会话进程会被自动停掉省内存，列表里显示「已回收」，点开自动重启，历史与草稿都在。

## 6. 与智能体对话

### 6.1 基本输入

Enter 发送；Shift+Enter 换行。中文/日文输入法组词期间按回车只确认候选词，不会误发消息。写清楚四件事效果更好：要完成什么、目标文件/目录在哪、输出格式与限制、完成后如何验证。

**每个会话都自带两条「交付纪律」**（追加在系统提示词里的硬规则，不需要你每次交代）：

1. 该问就问，不把假设当结论。你明确要求「先列出不确定项」时，它必须先集中列出缺什么信息、不同取值的后果、建议的默认值，再给可以先做的部分。
2. 引用依据要分清「文档明写」与「它的推断」：断言某件事违反/符合某条规定时必须指明出处；依据是推出的就要显式标注是推断。

### 6.2 附件

三种方式，效果相同（出现在输入框上方附件列表，随消息发送）：点 `+` 按钮选择文件；从导航栏「文件」tab 把文件行直接拖进输入框（拖悬时输入框出现高亮描边，同一文件重复拖入不会重复添加，目录不可拖）；从系统资源管理器拖文件进来，或直接粘贴图片。

### 6.3 斜杠命令与技能

点 `/ 命令` 按钮或在输入框敲 `/` 打开菜单（内置命令、扩展命令与技能三类）。常用：

- `/compact [说明]`：手动压缩上下文，可附压缩侧重点说明（等同上下文浮层里的压缩图标）。
- `/skill:名称 [参数]`：显式调用某个已安装的技能。
- 扩展包自带的斜杠命令也会出现在这里。

### 6.4 运行中追加指令

智能体正在回复时，输入框的发送按钮变为「停止」，同时支持两种追加方式（悬停发送按钮可见提示）：Enter 存为待处理后续，排队等当前轮结束后再执行；Alt+Enter 立即插入上下文执行（steer），尽快影响正在进行的任务。

已排队的消息显示在输入框上方，可「重新编辑」或点按钮立即执行。

### 6.5 草稿与发送失败保护

未发送的文本/图片/附件按会话落盘保存（最近 40 份），重启后自动恢复；发送成功、或删除到最后一个字符时清除。

任何发送失败（连接失败、RPC 报错等）都会回滚已显示的用户气泡，把原文本/图片/附件完整恢复到输入框，并弹错误提示。不会丢输入，也不会留下无响应的「幽灵消息」。

### 6.6 消息上的操作

- 悬停用户消息：复制这条消息 / 分支（见 5.4）。
- 智能体回复下方：复制、👍 有帮助 / 👎 没帮助（可写一句备注，再点一次可取消）。
- **选中文字后右键**（只在选中聊天区文字时弹）：引用到输入框 / 添加为待办 / 交接到新会话。引用会带上它在会话里的位置，不只粘一段死文本；「交接到新会话」把这段文字当作新会话的首条提示词直接发出去。
- 导航栏的会话行可以直接**拖到输入框**——松手后以会话引用附件的形式挂上，不用手动粘对话内容。
- 「完成提示音」开关在模型选择弹层的「会话工具」里，智能体完成任务时播放一声短促提示音，可关闭。
- 「思考中 · Ns」的计时是**整轮**计时（不会因为切会话归零），所以你切回来看到的仍是它实际跑了多久。

### 6.7 提问选择面板（choices）

有时智能体不直接问一句话，而是在回复里给出一个**可点选的面板**（比如让你从几个方案里挑一个）。这种面板会直接渲染在回复末尾，不是代码块。

怎么用：

- **逐题选**：每题点一个选项。选错了就重新点。
- **跳过**（每题标题右侧的小按钮）：不想回答这题就跳过。跳过的题**不会回传给模型**（整行省略），避免模型拿“随便”当答案。跳过的题可以「取消跳过」。
- **其它 / 自定义答案**：每题下面有「其它（输入自定义答案）…」，可以直接写一个选项里没有的答案。
- **补充说明**（面板底部）：给整组题加一段备注，写在最后一题之后；提交后仍可见，点击可改。
- **提交**：所有题要么选了要么跳了，底部按钮才可用（否则会提示「还有 N 题未选择」）。提交后你的选择会合成**一条**消息发出去（以「我的选择：」开头），面板随之冻结并显示你的选择。

几个用户不感知但要知道的点：

- 模型把面板格式写坏时，MPI 会**自动重试一次**（对用户无感），不会直接把一堆乱码椭给你。
- 同一条回复里出现多份面板时只渲染最后一个；正文为空的代码块不再被当成「格式不合法」报错。
- 提交后按钮会立即锁住，不会因为连点重复发送。

### 6.8 任务模式（一键切换工作方式）

任务模式是「权限档位 + 思考深度 + 可选行为指令」的命名预设，在输入框左下角、权限 pill 左侧的 ⚡ 按钮里切换（即时生效，不影响模型选择）。打开下拉，每一行显示名称与参数摘要（如「沙盒 · 低思考」），行尾的 ⓘ 可查看该模式的完整参数与指令；下拉底部的「管理任务模式…」可新建 / 编辑自定义模式。

内置四个模式：

| 模式             | 参数                         | 用途                                                                                   |
| ---------------- | ---------------------------- | -------------------------------------------------------------------------------------- |
| **均衡**（默认） | 沙盒权限 · 低思考            | 日常开发，推荐默认值。新会话自动套用。                                                 |
| **迭代**         | 完全权限 · 低思考 · 含说明书 | 按 loop-dev 闭环流程处理长任务：先侦察、拆解、给出计划等你批准，再逐步执行并逐项验收。 |
| **调研**         | 强制只读 · 中思考            | 只查不做：先给出带来源的完整调研报告，等你确认后再实施。                               |
| **审查**         | 强制只读 · 极高思考          | 只审不改：按严重度列出问题与修复建议，不直接改动代码。                                 |

- **强制只读**：调研 / 审查模式无论权限档位如何设置，激活期间任何写操作都会被系统拦截（这是安全底线，不可通过改权限绕过）。智能体给出方案后若需要动手，它会弹出「模式切换请求」卡片，点「同意并切换」即可实时放开当前会话的强制只读并继续执行（拒绝或关闭则保持只读）；想长期边调研边动手，可把参数复制成自定义模式。
- **自定义模式**：管理模式弹窗里可新建、编辑参数与指令；指令可以是一段文本，也可以指向一份外部 markdown「说明书」文件，激活期间每轮注入系统提示词（实时生效，改文件即可更新）。内置模式可改参数、不可删除。
- 应用模式时会批量设置所选参数；参数选「不改变」的项保持会话当前值。

## 7. 语音系统

MPI 支持双向语音交互：**语音输入**（说话 → 转成文字填入输入框）与**语音输出**（朗读智能体回复）。

### 7.1 语音输入（识别）

麦克风按钮在输入框底栏「添加文件」右侧：

1. 点击开始录音——按钮变红并显示脉冲点与计时；最长录 3 分钟自动停止，Esc 取消（不产生文本）。
2. 再点一次结束录音。音频在本机转成 WAV 后发给配置的识别服务转文字，结果**追加进输入框**（不会自动发送），可修改后再发。

**需要先做的一件事**：在「设置 → 对话设置 → 语音系统」里把「识别服务」选成 **OpenAI 兼容 /audio/transcriptions**，再填 Base URL 与模型名。没配置时麦克风按钮不可用。

MPI **不内置也不代管识别服务**，两种常见选择：

| 方式     | 做法                                                                                                                                                                        | 适合                         |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 云端服务 | 填服务商给的 Base URL + 模型 + API Key（如硅基流动等 OpenAI 兼容服务）                                                                                                      | 不想装东西，但要联网、有额度 |
| 本机部署 | 先在本机跑一个 OpenAI 兼容识别服务（如 sherpa-onnx + SenseVoice、FunASR、whisper.cpp、Speaches），Base URL 填服务地址（例：`http://127.0.0.1:8800/v1`），模型填服务端模型名 | 完全离线、不怕额度           |

凭证可以**引用「模型与提供商」里已配置的 provider**（地址/key 实时读取——改 key 不用重存语音配置），也可以手动填写 Base URL + API Key。**指向本机地址（`127.0.0.1` / `localhost` / `::1`）时 API Key 可以留空**；指向远程服务时必填。

「测试连接」按钮会发一段静音探针验证端点、key、模型是否都可用（静音探针返回空文本属正常）。

### 7.2 语音输出（朗读）

- **逐条朗读**：每条智能体回复右下角有「🔊 朗读」按钮（图标 + 文字），点击开始朗读该条，按钮变成「停止」且**在朗读期间始终可点**，再点立即停止。代码块折叠为一句“（代码块）”，链接只读文字，思考内容不读。
- **自动朗读**：在「设置 → 对话设置 → 语音系统」勾选「任务完成后自动朗读智能体回复」。当前可见会话每轮结束后自动读出回复；后台会话不打扰。

朗读引擎可选两种（「设置 → 对话设置 → 语音系统 → 语音输出」）：

- **系统语音（离线，默认）**：使用系统内置的语音合成（Windows 下即系统已安装的语音，中文需装有 zh 语言包），完全离线、无额外依赖。
- **Edge 在线神经语音（免费）**：由微软 Edge「大声朗读」服务合成，音色更自然，提供 13 个精选中英文神经音色（普通话 / 台湾 / 粤语 / 英美），无需 API Key，但**需要联网**。合成失败时（断网或服务不可用）会自动回退系统语音，并提示一次「已回退系统语音」。

两种引擎都可选声音（默认跟随界面语言、优先匹配语言的语音）、调语速 0.5×–2×，并可点「试听」。

如果朗读没声音：先切到「系统语音」试一下（能出声说明是 Edge 侧的网络/服务问题）；系统语音也无声音时，检查系统是否装了对应的语音包（Windows：设置 → 时间和语言 → 语言 → 语音）。

## 8. 权限模式

MPI 用权限门控制 Pi 执行 shell 命令、写文件和扩展操作的行为。每个会话独立设置，输入框左侧的权限 pill 可随时切换（即时生效，无需重启会话）。

| 档位         | 行为                                                                                                         | 适用场景                               |
| ------------ | ------------------------------------------------------------------------------------------------------------ | -------------------------------------- |
| 只读         | 只读操作可执行；任何修改类操作直接阻止且不弹确认。                                                           | 纯问答、代码分析，绝不想让 Pi 动文件。 |
| 严格         | 只读命令自动执行；所有写入/删除/修改类命令都需确认。对 write/edit 工具可选「本线程允许该工具」避免反复弹窗。 | 需要频繁改文件但想逐条把关。           |
| 沙盒（默认） | 项目内低风险操作（如 `npm run build`）自动执行；危险命令、写项目外位置等弹确认框。                           | 日常开发，推荐默认值。                 |
| 完全         | 不拦截任何操作。                                                                                             | 明确信任的任务/环境。                  |

- 新建会话默认权限：设置 → 权限与安全里的下拉框（只读/严格/沙盒/完全），控制之后新建会话的初始档位；已有会话保留各自设置。任务模式（见 [6.8](#68-任务模式一键切换工作方式)）会一并设定权限与思考档位，其中调研 / 审查模式强制只读。
- 工具信任列表：设置 → 权限与安全里有一个可搜索的「扩展工具信任列表」——自动列出本机会话中出现过的扩展工具（带搜索框 + 全部/已信任/未信任 tabs），打开某工具的开关后它在沙盒 / 严格权限下不再逐次弹审批（如 `mem0_memory`）；底部也可手动输入名称添加。`bash` 与写入 / 编辑文件的工具显示「始终需确认」，不可被信任；read/web_search 等只读工具本就无需审批、不提供开关；只读模式不受影响。
- **强制只读的拦截范围比想象中大**：调研 / 审查模式下，除了文件写入，**网络请求、非白名单命令、子智能体、大部分扩展工具**也一样会被拦。诚实的做法是它一开始就告诉你「当前任务模式无法完成这个请求」（而不是先试一堆命令再解释）。碰到这种情况直接切模式即可，不用改权限。
- 确认弹窗：需要授权时弹出「权限确认 / Permission required」，显示具体命令与目标路径，检查后再决定允许或拒绝。新手建议先看清命令和目标位置再放行。
- 定时任务无法等待人工授权，因此只提供沙盒/完全权限两档（见[第 11 节](#11-定时任务)）。

> 提示：权限门能显著减少误操作，但不能替代操作系统级隔离；对不信任的代码环境请配合系统沙箱使用。

## 9. 上下文管理

### 9.1 用量圆环

输入框底栏（模型选择器左侧）的圆环按钮实时显示当前会话的上下文占用：弧线 = 占比，颜色分四档，≤60% 绿 / 60–74% 黄 / 75–89% 橙 / ≥90% 红。切换会话时加载，流式结束/压缩完成即时刷新，运行中每 15 秒轮询。

### 9.2 上下文窗口浮层

点开圆环查看：当前模型名、进度条、「~已用 / 总量 + 百分比」、「已压缩 N 次」（悬停显示最近一次时间）、按占用档位着色的压缩建议，以及右上角的刷新与压缩图标。

- ≤60%：暂无需压缩
- 60–74%：长任务可提前压缩
- 75–89%：建议手动压缩留出空间
- ≥90%：强烈建议立即压缩
- 累计压缩 ≥3 次时追加提醒：早期细节可能丢失，重要结论建议写入文件或记忆。

### 9.3 压缩上下文

三种触发方式：浮层右上角的压缩图标（等同 `/compact`）；输入框敲 `/compact [说明]`；长对话达到阈值时 pi 自动压缩（失败会弹警告提示）。

压缩后 token 数显示为估算值（带 `~` 前缀），直到下次回复拿到真实数字。

**压缩后仍能看回原文**：压缩不是把旧消息删掉，它们在对话里被一条分隔条括起来，上方是「更早的对话」区域——默认折叠，点一下就展开（题长时间对话首次加载不卡），会话内搜索（Ctrl+F）也能搜到里面的内容。

**想省钱的可以用便宜模型做摘要**：「设置 → 模型与提供商 → 摘要模型」（提供商 + 模型两行）。不填 = 跟随会话主模型；主模型用贵的云端大模型、压缩走便宜的 flash 模型是个常见搭配。改完下一次压缩即生效，无需重启。

### 9.4 砖会话一键修复

极少数情况下，provider 会因「空白 tool result」或「孤儿 tool_result」拒绝整个会话历史，导致无法继续对话。此时输入框上方出现红色横幅与「一键修复并重新加载」按钮：MPI 修复会话文件（占位替换、清理过期压缩记录），修改前自动备份到 `sessions/mpi-repair-backups/`，完成后自动重开会话。

## 11. 定时任务

导航栏的时钟图标打开「定时任务」面板。注意：调度只在 MPI 运行时进行，应用关闭期间不会执行任何任务。

### 11.1 新建任务

点 `+`，填写：

| 字段       | 说明                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 任务名称   | 例如「每日晨报」。                                                                                                           |
| 工作文件夹 | 任务运行的项目目录（Pi 在该目录下工作）。                                                                                    |
| 提示词     | 到点要执行的完整指令；可以使用已安装的技能。                                                                                 |
| 重复       | 每小时（第 N 分钟）/ 每天（HH:mm）/ 每周（勾选星期 + HH:mm）。                                                               |
| 运行权限   | 沙盒（默认，需要确认的操作会被阻止）或完全。定时任务无法等待人工授权，请只给明确信任的任务开完全权限。                       |
| 模型       | 可选。不填 = 用当前设置的默认模型；填了就固定用这个提供商 / 模型跑，适合「便宜的模型干机械活」。列表带上每个任务的模型徒标。 |

> 定时任务是无人值守运行的，所以它对「需要人工交互」一律按失败处理而不是傻等；只有发通知类的操作会被放行。

### 11.2 管理任务

每行显示名称、调度摘要、上次状态（失败会标红并悬停显示原因）、启用开关。「立即运行」按钮手动触发一次；「编辑」修改后保存；删除带确认。

任务执行结果以独立会话出现在对应项目下，会话名前缀为「定时任务: xxx」（旧版创建的「自动化: xxx」仍会被识别并随语言本地化）。完成/失败会弹 toast 通知。

## 12. 待办任务

导航栏的方框对勾图标打开「待办任务」面板。待办按项目记录，支持截止日期（可精确到分钟）、备注、文件/图片附件与智能日期解析；智能体也可以在对话中直接添加待办（带 AI 标记）。

### 12.1 添加待办

在面板顶部输入框直接输入文字回车即创建。左侧选中「全部项目」时，先用下拉框选择目标项目；选中某个具体项目后，新待办自动归属该项目。

也可以在聊天里选中一段文字后右键「添加为待办」——它会带着这段文字的**来源会话位置**一起存下来，以后回到待办能直接跳回原对话。

智能日期解析：可以在文字里直接写日期。`明天发周报` 会变成标题「发周报」、截止明天；也支持 `周五`、`9月30日`、`12-5` 等写法；识别不到日期则作为无日期待办。时间可以跟在日期后面：`明天9点开会` → 明天 09:00；`下午3点半评审`、`14:30交报告`、`9am standup` 都可以。只写时间不写日期时默认今天（如 `14:30交报告`）。

点击某一行展开行内编辑器：可修改标题 / 备注 / 截止日期与时间（或清除日期）后保存，也可以直接删除（不弹确认框）。

附件：描述下方的虚线框就是附件区（飞书多维表格式），左侧常驻一个 ＋ 方块。点击它弹出系统文件选择框；也可以直接把文件/图片拖拽进编辑器（拖入时虚线框会高亮提示），或点击虚线框内空白处后按 `Ctrl+V` 粘贴。每条待办最多 10 个附件、单个不超过 50 MB。重复添加同一文件（再次选择/粘贴/拖入同名同大小的文件）会自动去重，只保留一份并给出提示。已有附件显示在卡片里：图片为缩略图（点击打开全屏预览浮层，右上角可放大/缩小，Esc 关闭），其他文件显示文件名与大小（点击用系统默认程序打开）；悬停卡片出现 × 移除。附件以副本形式存储（删除原文件不影响待办），默认位置 `%APPDATA%\MPI\todo-attachments\`，可在设置 → 数据管理中更改（已有附件保留在原位置）。

### 12.2 智能分栏

面板按时间维度分组，每个 chip 显示数量：全部 / 今天（含已过期，过期标红）/ 明天 / 本周（周一至周日）/ 稍后（本周五之后的日期）/ 无日期 / 已完成。在「已完成」分栏底部可点「清空已完成」批量删除当前范围内的已完成项。

### 12.3 项目范围与智能体协作

左侧列选择某个项目即只看该项目的待办；「全部项目」显示所有项目的待办，行上带项目名标签。智能体在对话中调用 `mpi_todo_add` / `mpi_todo_list` 工具时，会通过收件箱机制写入本面板（主进程监听并去重入库）；这类行右侧有 AI 徽标，点击直接跳转到来源会话。数据存于 `%APPDATA%\MPI\todos.json`（见[第 22 节](#22-数据与配置位置)），dev 版与正式版相互独立。

## 13. 扩展功能：技能 / 扩展包 / MCP

导航栏的插头图标打开「扩展功能」面板（管理 pi 的扩展包与技能），顶层三个模块 tab：技能 N / 扩展包 M / MCP K（各带计数）。

### 13.1 技能

技能是 `SKILL.md` 形式的指令集，pi 在合适时机自动加载，也可用 `/skill:名称` 显式调用。三个子 tab：

- 我的技能（主从布局）：左列搜索 + 全部/已启用/已禁用过滤 + 按来源目录分组列表；右列详情栏有徽章、「复制命令」（把 `/skill:name` 写入剪贴板）、启用/停用开关、SKILL.MD 渲染预览与「复制 Markdown」。
- Skill 市场：浏览搜索 [skills.sh](https://skills.sh/) 公开目录并一键安装到 Pi；搜索框上方固定横条提供其他市场外链（虾评 / SkillHub / SkillsMP）。
- 统计：总数/已启用/已禁用统计卡、按来源目录分布条、已禁用技能列表（可一键重新启用）。

### 13.2 扩展包

pi extension 是 npm/git/本地路径安装的代码扩展，可为 pi 增加工具、命令与 UI。两个子 tab：

- 我的扩展包：顶行「＋安装扩展包 / 更新全部」；点 ＋ 展开内联输入框（支持 `npm:<包名>`、`git:` 地址或本地路径，Enter 安装）。左列按 npm/git/local 分组列表 + 右列详情栏（类型/版本徽章、来源与安装目录、package.json 说明、更新/启用停用/移除按钮）。
- 扩展包市场：搜索公共 npm registry（默认查询 "pi extension"，前 30 条按相关度排序）；左列结果列表 + 右列详情栏（版本/license/周下载徽章、npm 页面与仓库链接、README 预览），一键安装走 `npm:<包名>`。

> 扩展包安装使用 MPI 内置的 npm，未安装 Node.js 的电脑也能装；从 git 源安装需要系统装有 Git（缺失时会给出明确提示）。若你手动配置过 `~/.pi/agent/settings.json` 里的 `npmCommand`，MPI 不会覆盖它。

### 13.3 MCP

MCP（Model Context Protocol）服务器为 pi 提供外部工具与数据源。两个子 tab：

- 我的 MCP：左列列出 `~/.pi/agent/mcp.json` 中已配置的服务器（stdio / remote 徽章，另有 exposure 徽章）；右列详情栏有命令复制、启用/停用开关（写 pi 认的 `enabled: false`，可随时恢复）、删除（带确认）。
- MCP 市场：浏览 mcpmarket.cn 公开目录（logo/作者/stars/简介），支持关键词搜索与「加载更多」；点卡片查看中英文 overview 分节与 GitHub 链接。

> **MCP 由 pi 内建实现**（pi ≥ 0.99）：不再需要 `pi-mcp-adapter` 扩展，面板也不再要求安装它。改完配置后在会话里 `/reload` 生效，`/mcp` 看连接状态与登录 OAuth。两个注意项：① 旧版本 MPI 写的 `disabled: true` 会被自动改写成 `enabled: false`；② 内建的默认 `exposure` 是 `codemode`，即模型不直接看到一堆 `mcp__*` 工具而是按需取用——希望某个服务器的工具直接可见，就给它的条目加 `"exposure": "direct"`。

### 13.4 扩展选模（免弹窗）

部分扩展需要调用模型时会弹窗让你选择（典型：pi-web-access 联网搜索每次打开浏览器整理窗口并询问摘要用哪个模型）。设置 → 对话设置 →「扩展选模」（默认开）开启后：

- **不弹窗**：扩展的模型选择请求由 MPI 自动应答，直接使用当前会话的模型；定时任务（无人值守）同样生效。
- **联网搜索免浏览器窗口**：pi-web-access 改为 `auto-summary` 工作流——搜索完直接返回 AI 摘要，不再打开浏览器整理页；单次调用仍可传 `workflow: "summary-review"` 恢复交互式整理。
- **摘要模型跟随会话**：每轮开始时把当前会话的模型写入 `~/.pi/web-search.json`（与终端 pi 共享），切模后立即生效；摘要超时放宽到 5 分钟，本地慢速模型也能出完整摘要。MPI 首次修改该文件前会备份原值，关闭开关时精确还原。

侧栏底部的「知芽 Zhiya」按钮打开一个窄列菜单（所有版本都开放，不限于开发版）：

| 模块     | 作用                                                                                         |
| -------- | -------------------------------------------------------------------------------------------- |
| 人物画像 | `~/.pi/agent/zhiya/persona.md`，注入每个会话的系统提示词，见 [4.7](#47-用户画像已并入知芽)。 |
| 协作约定 | 一套协作规则的 md，适合写「哪些事必须先问我」这类硬规则。                                    |
| 工作空间 | 工作空间布局说明的 md。                                                                      |
| 知识库   | 浏览当前项目的 `.alexandria/knowledge/`（文件树 + MD 预览）。                                |
| 当前任务 | 侧板形式展示正在跑的任务。                                                                   |
| 记忆池   | 侧板形式浏览/检索/批量处理记忆条目。                                                         |

- **归档不是删除**：`/memory-forget` 只是移入归档目录，随时可找回。

## 14. 终端与 Pi TUI

右侧槽有两种面板：**预览**和**集成终端**，二选一（宽度可拖动，按钮可以展开 / 关闭）。

### 14.1 集成终端（默认入口）

聊天顶栏的 **⌨ 终端**按钮在右侧槽打开一个真实终端：

- 跑的是**你自己的 shell**（Windows 下为 Git Bash），不是 pi —— 用来手敲命令、看输出、在需要交互的地方输密码/账号（这类东西输不进对话框）。
- 工作目录**跟着当前会话**：切会话就换目录，不会拿旧目录的 shell 继续跑。
- 面板头部有「重开终端」（清屏 + 新 shell）；面板宽度与其它右栏面板一致，可拖拽。
- 再点一次顶栏按钮就关掉（同一时间右侧槽只显示一个面板）。

### 14.2 Pi TUI（旧交互模式，可选）

旧版本把整个会话区切换成交互式 pi 终端；现在这个入口已不再是默认方式。如果你习惯用它，它仍然与 GUI 共用同一会话：

- 共用同一会话文件与工作目录，历史双向共享；在终端里发的消息切回 GUI 后照样可见；
- 进入前若正在回复会先自动中止；
- 退出：在终端里 `/exit` 或切到别的会话；
- 窗口缩放时终端尺寸跟随。

> 简单说：**想看文件、查输出、跑命令 → 用右侧集成终端**；**想用 pi 自己的 TUI 命令（`/fork`、`/model` 等）→ 用 Pi TUI**。两者不冲突。

## 15. 全局搜索（Ctrl+K）

导航栏顶部 🔍 按钮或 Ctrl+K 打开全局会话搜索：输入关键词，全文匹配所有会话的标题与消息内容。「归档回收」复选框勾选后同时搜索已归档会话与回收站条目，结果行带状态徽标（已归档 / 项目已归档 / 回收站），每行附「恢复」按钮可直接恢复到导航栏。Esc 或点右上角退出键关闭。

### 15.1 会话内搜索（Ctrl+F）

会话顶部工具栏最左侧的 🔍 按钮，或 Ctrl+F，打开当前会话内的搜索条：

- **搜得到全部历史**：包括已经被压缩的「更早的对话」（命令命中时会自动把这整段历史展开并定位过去）。
- **导航粒度是消息**（不再拆成碎片段），Enter / ↓ 下一个，Shift+Enter / ↑ 上一个（首尾循环），自动滚到命中处。

- Esc 或点 × 关闭，关掉即回到正常阅读态（高亮一并撤销）。
- 搜索不扫思考块与工具调用参数。

### 15.2 左侧消息导航

会话左侧的竖排圆点条：每行默认显示 20 字预览，**悬停（或 Tab 聚焦）某一行会弹出完整的输入文本**，长消息不用点进去就能看清。压缩过的会话里，压缩前的那段也算在导航里。

## 16. 归档与回收站

**设置 → 数据管理 → 归档与回收**页统一管理三类条目，均按项目分组（组头显示项目名 + 计数，可折叠）；顶部搜索框同时过滤三类（标题/项目名/路径子串匹配）：

| 区块       | 内容                                                                            | 操作                                              |
| ---------- | ------------------------------------------------------------------------------- | ------------------------------------------------- |
| 已归档项目 | 整个被归档的项目                                                                | 恢复项目。                                        |
| 已归档会话 | 单个归档的会话（显示归档时间，悬停可见完整文件路径）                            | 恢复到原项目。                                    |
| 回收站     | 删除的会话（默认开启；显示删除时间 + 占用大小），头部可「清空回收站」（带确认） | 「恢复会话」回到原项目 / 「永久删除」（带确认）。 |

规则：归档是可逆的整理手段，不影响文件本身。删除默认先进回收站（`<userData>/trash/`），只有从回收站里再删才算永久删除；在「设置 → 数据管理」关闭回收站开关后，删除立即永久生效（已入站的条目仍可恢复/清空）。

附加能力：多个会话可以一次性处理（右键 →「批量操作」，批量归档 / 删除 / 导出，见 [3.2](#32-导航栏左侧)）；导出的产物是**能再导入回 MPI 的会话包**（zip），与 [5.6](#56-导出会话包)相同。

> 退出 MPI 时，应用商店里正在跑的应用服务会被一并停掉（不会留在后台）。

### 17.2 凭据（本机凭据库）

只存**本机**的密码 / 令牌 / 私钥口令（Windows 下用系统加密 DPAPI），**值永远不出主机**。适合放「智能体干活时需要，但你不希望它被写进对话、日志或快照」的东西。

**要求与限制**（写错很容易存不进去）：

| 字段   | 规则                                                                      |
| ------ | ------------------------------------------------------------------------- |
| 名称   | 2–64 位，只允许小写字母 / 数字 / `._-`（如 `aliyun-prod-root`），不能重名 |
| 类型   | 密码 / 令牌 / 私钥口令 / SSH 私钥                                         |
| 作用域 | 全局，或限定到某个项目 / 目录                                             |
| 值     | 不能为空；本机加密不可用时**拒绝保存**（不会退化成明文）                  |

**等级（决定远程会话能不能用）**：

| 等级       | 含义                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| 远程直接用 | 远程会话也能直接用（适合只读查询、最小权限账号）。会话启动时注入为环境变量。 |
| 远程需确认 | 远程使用时需在手机端点一次确认（需授权）。                                   |
| 仅本机     | 任何远程来源一律拒绝，只能在本机用。                                         |

**怎么用**：

- 智能体自己看不到明文。它知道有哪些凭据、能不能用、不能用是什么原因（比如「已拒绝：仅本机」），需要时调 `mpi_secret_run` 跑单条命令，凭据以环境变量 `MPI_SECRET_VALUE` 的形式交给那条命令，**值不会进入对话**。
- 「远程需确认 / 仅本机」级需要你在「允许执行」卡片上点同意才会跑（桌面与手机都能看到这张卡）。
- 列表里只显示掩码；点「显示」会在 **15 秒**后自动收起（避免定格在屏幕上），每次显示 / 复制都会留一条审计记录。
- 删除需二次确认；删掉的凭据智能体立刻就看不到。

### 17.3 服务器

要把手机 / 网页版接到本机时在这里配置，分两张卡：

- **转发设置**：默认走内置服务器（需先在「激活授权」里填激活码）；也可以勾「自定义中继（使用自建中继）」自己部署——填中继地址（`ws(s)://<主机>:<端口>/ws`）与准入令牌，然后点「验证连通性」，显示「转发通道可达」才算通。面板里带一份「如何设置自己的中继」分步说明。
- **激活授权**：设备标识 / 设备名称 / 粘贴激活码。未激活时只能用局域网与本机中继。

注意：中继只转发数据帧、不解析内容（端到端加密）；令牌只随主机注册与镜像请求发送，不写进配对二维码，也不下发给手机。有未保存修改时关设置会被提醒——以前改了没点保存就重启会被旧配置悄悄还原。

### 17.5 权限与安全

| 项                     | 说明                                                                                                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新建会话默认权限       | 只读 / 严格 / 沙盒 / 完全，控制之后新建会话的初始档位。详见[第 8 节](#8-权限模式)。                                                                                                                           |
| 扩展工具信任列表       | 可搜索的本机会话中出现过的扩展工具列表，带全部/已信任/未信任 tabs 与开关，一键切换信任；底部也可手动输入名称添加。                                                                                            |

### 17.6 数据管理

分三段：**存储位置**、**归档与回收**、**备份与恢复**，另有回收站开关。

| 项         | 说明                                                                                                                                                                                                                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 回收站     | 删除的会话先移入回收站（可恢复）；关闭则删除立即永久生效。详见[第 16 节](#16-归档与回收站)。                                                                                                                                                                                                                                 |
| 存储位置   | 两个独立位置可改到本机任意目录：**会话存储位置**（默认 `~/.pi/agent/sessions`，保存所有 pi 会话记录 `.jsonl`，改动会同步写入 `~/.pi/agent/settings.json` 的 `sessionDir`，终端 pi 也跟随）与**待办数据位置**（默认应用配置目录 `%APPDATA%\MPI`，保存 `todos.json`、附件 `todo-attachments\`、智能体收件箱 `todos-inbox\`）。 |
| 归档与回收 | 见[第 16 节](#16-归档与回收站)。                                                                                                                                                                                                                                                                                             |
| 备份与恢复 | 应用设置与会话两套独立备份，各有导出 / 导入按钮（见下）。                                                                                                                                                                                                                                                                    |

存储位置更改分两步生效：选完新目录后只记录「意图」，该行下方出现橙色提示（"位置已更改，文件将在下次启动时迁移。重启前应用仍读取旧位置"）；完全退出 MPI 再启动后，全部文件在窗口打开前自动迁移。迁移规则：

- 会话文件平铺进自定义目录（pi 的 sessionDir 布局不按项目嵌套）；「恢复默认」时按各文件头 cwd 重新归入 `sessions/<项目目录>/`；
- 设置里指向旧会话的路径引用（权限记录、草稿、回收站索引、AI 待办的来源会话链接）自动同步更新；
- 目标已有 `todos.json` 时不覆盖，该项保持 pending，下次启动重试（其余文件正常迁移）；失败项同样保留重试；
- 旧位置的附件在迁移后仍可正常打开 / 删除。

自定义位置时每行显示「恢复默认」按钮；悬停路径文字可查看当前生效目录。迁移结果记录在控制台（`[migration]`）。

备份与恢复（两套相互独立的对象）：

- **应用设置**：把应用配置（`config.json`：主题、语言、置顶、头像、用户画像、定时任务、远程信令等）导出为单个 JSON 文件（默认名 `mpi-config-backup-<日期>.json`）。导入时先显示可识别的设置项数量并要求确认，确认后只覆盖备份里包含的对应项（其余设置保持不变）。模型提供商 / 思考默认值存于 `~/.pi/agent`（与终端 pi 共享），不在本备份范围内；机器相关项（pi 路径、窗口位置）导入时永不恢复。
- **会话**：勾选要导出的项目（可全选 / 清空，显示每个项目的会话数与占用大小），把所选会话的原始 JSONL 文件打包为 zip（`mpi-sessions-backup-<日期>.zip`，保留项目目录结构）。导入时先提示「N 个新会话 / M 个已存在」：默认只导入新的、跳过已存在的文件；如需以备份为准恢复，选「覆盖全部」。导入后会话回到原属项目（导航栏自动刷新）。

典型用途：换新电脑迁移、大改动前留快照。

## 18. 手机远程控制（网页版 / 安卓）

入口：导航栏底部的手机图标（「手机远程控制（云中继）」）。面板只有两块——**配对**与**设备**。

### 18.1 配对

打开面板就会自动生成一个二维码（带倒计时，票 **5 分钟**失效，过期点「重新生成」）。手机上：

1. 扫码（或把「另一台电脑」链接复制到那台机器的浏览器）；也可复制 App 链接粘贴到安卓 App 的配对框。
2. 桌面端（或手机端）确认后，设备进入「已信任设备」列表。

一个已知的坑：**票只能换一次设备身份**，一个二维码发给第二台手机就会失败——每台手机各自扫码。

### 18.2 设备管理

- **待批准**：有才出现，逐条允许 / 拒绝。
- **已信任设备**：在线优先，可重命名、可随时撤销。同一台手机不会重复绑定（按公钥认设备，同名离线设备会被替换）。
- 顶部状态行里有「诊断」折叠：手机将连的地址、内网入口、局域网开关、原始错误码——接不通时先看这里。

### 18.3 传输与安全

- 手机端不直连桌面，而走**中继**（在[设置 → 服务器](#173-服务器)里配）；中继只转发数据帧、不解析内容。
- 主机侧做了 **身份绑定（pinning）**，中继无法靠换公钥冒充你的桌面端。
- 手机上的权限更保守：即使桌面端是沙盒 / 完全权限，**敏感命令仍需在手机上确认**；强制只读（任务模式）在手机上不会被绕开。

### 18.4 会话配置双向同步（权限 / 模型 / 任务模式 / 思考等级）

手机上改的，桌面立刻变；桌面上改的，手机也立刻变。四个配置项都走同一条广播：

| 方向        | 操作                                           | 结果                                             |
| ----------- | ---------------------------------------------- | ------------------------------------------------ |
| 手机 → 桌面 | 在手机上切权限、切模型、切任务模式、改思考等级 | 写进桌面配置与当前进程的权限门，桌面界面同步刷新 |
| 桌面 → 手机 | 在桌面上改同样四项（或由智能体自己改）         | 手机上的标片与任务模式跟着变，不用重新进会话     |
| 手机 → 手机 | 同一台手机开多个页面                           | 后一个页面会接手写权限，旧的自动退让             |

两个需要知道的细节：

- **手机上只能看到两档权限**：「沙盒」与「完全」。桌面上的「只读」或「严格」在手机上会被收拢为这两档之一，具体档位只能回到桌面看。
- **同一会话同时只能有一台设备在改**：修改类操作需要先拿到写租约（默认 30 秒、每次写入自动续期），别的设备持有且未过期时会提示「该会话正被其他设备操作」。连接断开后租约自动释放。

> 这意味着你可以把任务丢给桌面，用手机在通勤路上把权限从沙盒改到完全（或反过来收紧），不用回到电脑。

### 18.4 手机上能做什么

网页版（PWA）与安卓 App 能力一致：对话即主页（首屏就是对话，不另存一份会话列表）、可切换会话、发文字 / 图片 / 视频 / 音频（附件走直连，大视频点开才拉；看过的视频本地缓存，第二次不再重下）、可跑多题选择面板、可「交接新对话」、可批准审批、可重命名 / 置顶 / 删除会话、可切权限 / 模型 / 任务模式 / 思考等级（与桌面实时双向同步，见 [18.4](#184-会话配置双向同步权限--模型--任务模式--思考等级)）。

几个手机端专属的便利：

- **上下文用量也能看**：手机上同样有占用圆环，能直接发起压缩。
- **有新版本会提示**：网页版顶部出现「有新版本 · 点击刷新」，不会让你停在旧代码上。
- **拖拽与粘贴附件**：网页版也支持拖文件进来或直接粘贴图片。
- **回前台自动补同步**：切回页面时只拉增量，不整页重置（断线期间的事件不会丢）。

> 安卓壳还额外提供：右上角 `⋮` 菜单、扫码配对、原生录音、APK 自更新。

## 19. 消息接入（飞书 / 微信）

在飞书或微信里给机器人发消息，就能驱动 MPI：私聊（飞书还支持群里 @它），消息会进入绑定项目下的专属会话执行。飞书的回复流式更新回同一条消息；微信在处理中显示「正在输入」，完成后单独发一条结果消息。两个渠道都仅在 MPI 运行期间在线。

### 19.1 启用渠道

打开 **导航栏 → 消息接入**（「新建会话 / 定时任务 / 扩展功能」下方第四项）。面板左列为通道列表：飞书 / 微信，点击切换。

推荐：扫码一键接入。点右侧快速接入卡的「📱 扫码选择或创建应用」→ 手机飞书扫码 → 在确认页二选一：**选已有应用**（复用你企业里已建好的机器人，页面会展示本次将追加的权限/事件差异并需再次授权）或 **立即创建**（自动在你的企业下新建机器人应用，预配好权限与事件订阅）。确认后 App ID/Secret 直接写入本机配置，无需手动找凭证，App Secret 全程不离开本机。若你的环境不可用扫码接入，再用下面的手动方式：

| 字段                | 说明                                                               |
| ------------------- | ------------------------------------------------------------------ |
| 启用飞书接入        | 总开关；关闭时不建立任何连接                                       |
| App ID / App Secret | 飞书开放平台自建应用的凭证（Secret 只保存在本机，保存后不再回显）  |
| 绑定项目            | 消息执行所在的项目文件夹；其下会自动创建名为「飞书接入」的专属会话 |
| 会话权限            | 沙盒（默认，阻止需要确认的操作）/ 完全权限                         |

点 **保存配置** 立即生效。面板顶部状态灯：灰 = 未启用、黄闪 = 连接中/重连中、绿 = 已连接、红 = 失败（下方显示错误详情）。

**微信**：点快速接入卡的「📱 扫码连接微信」→ 用手机微信扫码确认（部分账号需按提示输入数字验证码）→ 凭证自动保存，无需注册企业、配置回调地址。然后选绑定项目、打开总开关，点 **保存配置**。已绑定时显示打码的 botId，可「重新扫码连接」覆盖当前凭证；状态灯含义与飞书相同。

### 19.2 创建飞书应用（首次使用）

> ⚠️ 前提：必须有企业/组织。飞书开放平台要求自建应用挂在企业租户下，且长连接事件推送仅支持企业自建应用。如果你的账号是个人版（没有企业），请先免费创建一个自己的企业（个人可自建，无需营业执照，创建后你就是管理员）。否则会出现「能连上但永远收不到消息、后台找不到发布入口」的现象。

1. 登录 [open.feishu.cn/app](https://open.feishu.cn/app)（没有企业先按上面提示创建一个）；
2. 创建企业自建应用，在「凭证与基础信息」记下 App ID 和 App Secret；
3. 「应用能力 → 机器人」添加机器人能力；
4. 「权限管理」开通：`im:message.p2p_msg:readonly`（接收单聊消息）、`im:message.group_at_msg:readonly`（接收群聊 @机器人 消息）、`im:message:send_as_bot`（以应用身份发消息）；
5. 「事件与回调」选择使用长连接接收事件，并添加事件 `im.message.receive_v1`（接收消息 v2.0）；
6. 创建版本并发布（或先设置测试可用范围）。

> 长连接模式无需公网 IP、无需内网穿透，MPI 直接连飞书的 WebSocket 端点。面板里也内置了这份指南。

### 19.3 使用与命令

- 私聊：直接给机器人发文本；
- 群聊：@机器人（只有 @它的消息会被处理，且需先开通 `im:message.group_at_msg:readonly` 并把机器人拉进群）；
- 绑定的文件夹如果还不是 MPI 项目（没有会话），保存配置时会自动置顶到导航栏，方便查看飞书会话落在哪里；
- 回复先显示「🤔 正在处理」占位，随后随 agent 输出流式刷新，完成后定稿；内容过长会截断（完整结果在 MPI 会话里查看）。

微信渠道仅支持**私聊与文本消息**（无群聊；图片/文件暂不支持）：直接给 bot 发文本即可，处理中微信侧显示「正在输入」，完成后单独收到一条结果消息。一个微信账号绑定一个 MPI 实例。

命令（飞书 / 微信通用）：`/new` 新建会话（旧会话保留）、`/list` 列出本项目最近会话、`/use <序号>` 切换到指定会话（如 `/use 2`，也支持直接填会话 ID）、`/help` 帮助。当前活跃会话会被记住，重启后自动恢复（若该会话已不存在则回落到渠道专属会话）。

飞书 MCP：表单底部「启用飞书 MCP」按钮把官方 `@larksuiteoapi/lark-mcp`（npx stdio）以当前渠道凭证写入 `~/.pi/agent/mcp.json`，会话中的智能体即可直接调用飞书 API（默认工具集：消息 / 文档 / 日历 / 多维表等）。对新会话生效；可在「扩展功能 → 我的 MCP」中停用或删除。需本机已安装 Node.js ≥ 20。

同一时间只处理一条消息，处理中再发会收到「还在处理中」提示。

### 19.4 注意

- 渠道仅在 MPI 运行时在线；MPI 未运行（或连接断开）期间发送的消息不会被接收；
- 建议不要在桌面端与聊天工具同时操作同一个专属会话，以免互相干扰；
- 更换绑定项目后，会在新项目下新建渠道专属会话（「飞书接入」/「微信接入」）；
- 微信通道是腾讯灰度中的个人微信 bot：若扫码后长时间无反应或提示不可用，说明账号暂未在开放范围内；凭证失效时渠道自动停止，面板会提示重新扫码。

## 20. 应用商店

**应用商店**是 MPI 的**应用加载平台**（类似微信小程序）：MPI 只负责**导入、安装、托管、卸载**，应用本身的全部文件——清单、服务代码、运行时依赖、模型——都由开发者打包后导入，**MPI 安装包里不内置任何应用**。应用是**自包含应用包**，可以自带：①**服务模块**（在 MPI 主进程里运行，负责探测/启动服务、上报状态与日志）②**pi 扩展**（启用后自动注入新会话）③**运行时与模型**（放在包内，导入即用）。启用时 MPI 写好对应设置（停用时精确还原，你手动改过的字段不会被覆盖），并加载应用的服务与扩展。

> **信任提示**：带服务模块或扩展的应用会以 MPI 主进程权限运行（与 pi 插件同一信任模型，本轮没有沙箱）。因此**安装声明了能力的应用时 MPI 会弹确认框**，列出该应用要求的能力（如「启动与管理子进程」「访问网络」）。请只安装你信任来源的应用。

> 和「扩展功能」的区别：扩展功能管理的是通用 pi 技能 / 扩展包 / MCP 服务器；应用商店里的应用是 MPI 客户端本身的功能接入，并且可以自带自己的扩展。两者互不影响。

### 20.1 打开与导入应用

1. 点左侧边栏的**应用商店**（在「扩展功能」下方）。
2. 导入应用有两种方式：
   - **从 zip 安装**：选择开发者打包好的自包含 `.zip`（含清单、服务、运行时、模型）。
   - **加载目录**：选择已解压的应用目录（含 `mpi-app.json`）；想自己改应用文件时用这种。
3. 导入成功后出现卡片：应用名、版本、分类、简介和当前状态（已安装 / 已启用）。
4. 点任意卡片进入详情页，查看部署指引与配置表单；左上角箭头返回列表。

### 20.2 第一个应用：本地语音服务（装好即用）

这个应用把**离线语音识别**接入 MPI 的语音输入（麦克风按钮），实现完全离线的听写。它**自带运行时与模型**：启用时会用包内的 sherpa-onnx 运行时和 SenseVoiceSmall 模型**自动启动一个本地识别服务**，无需你事先安装或部署任何东西。

**步骤**：

1. 从 zip 安装**本地语音服务**（首次会弹**能力确认框**，列出「启动与管理子进程」「访问网络」，确认后继续）。
2. 详情页表单一般**保持默认即可**：
   - **外部服务地址**：留空 = 使用应用自带的内置服务；若你自己已有一个 OpenAI 兼容 STT 服务，可填它的 `/v1` 根地址（如 `http://127.0.0.1:8820/v1`），此时应用**不再启动内置服务**，只做探测。
   - **内置服务端口**：默认 `8800`；被占用时应用会自动换一个空闲端口。
   - **模型名**：默认 `SenseVoiceSmall`。
3. 点「启用应用」→ 详情页出现**服务状态**（启动中 / 运行中 / 异常 / 已停止）与「查看日志」。首次启动要加载模型，可能需要十几秒；状态变**运行中**即已接入。
4. 打开 设置 → 对话设置 → 语音系统 可复核：识别服务为 OpenAI 兼容、地址指向 `http://127.0.0.1:8800/v1`。此后点输入框的麦克风按钮说话，就用这个内置服务听写。
5. 若状态显示「异常」，点「查看日志」看原因；点「重启」可重试。

### 20.3 自己做/打包一个应用

应用包是一个**自包含 zip**，最小的包根只需一个 `mpi-app.json`（清单 + 配置表单 + 可选的 service / pi 扩展 / capabilities 声明）。要带运行时和模型时，约定用 `runtime/` 与 `model/` 两个目录，服务模块可用 `host.execPath` + `ELECTRON_RUN_AS_NODE` 直接拉起包内的 Node 服务，无需外部 node/python。

- 参考实现与说明：仓库内 `examples/apps/local-voice/`（`README.md` 有打包流程）。
- 一键打包：`node scripts/build-app-pack.mjs --app=examples/apps/local-voice`（自动准备当前平台的运行时与模型并打成 `<id>-<平台>-<架构>.zip`）。
- 生成 zip 后，在应用商店点「从 zip 安装」导入即可。

> 应用包以 MPI 主进程权限运行（无沙箱）。请只安装信任来源的包。

### 20.4 停用与卸载

- **停用（还原设置）**：只回滚该应用写入的字段；启用后你手动改过的某个字段会保留你的修改，不会被还原覆盖。同时会**结束应用托管启动的服务进程**（内置服务随之停止），并卸载应用自带的 pi 扩展（新会话不再加载；你自己放在 `~/.pi/agent` 的扩展不受影响）。
- **卸载**：带确认框。删除应用的安装文件与保存的表单值；若卸载时处于启用状态，会先停用并还原设置。

### 20.5 如果没生效怎么办

**服务状态一直显示「异常」/「已停止」**
点「查看日志」看探测/启动结果。若用的是内置服务，确认包内 `runtime/` 与 `model/` 存在（zip 是否完整）；若填了外部服务地址，连接被拒绝多半是服务没启动或端口填错。改好后点「重启」。

**启用后语音输入还是走旧服务**
应用写入的是「设置 → 对话设置 → 语音系统」；如果你在启用后又手动改过识别服务（比如切回云端），MPI 以你最新的手动配置为准——这是设计如此。想重新用本地服务，再启用一次该应用即可。

**列表是空的**
说明还没导入任何应用。点顶部「从 zip 安装」或「加载目录」导入第一个应用。

| `Ctrl+K`            | 全局会话搜索                                                                                                                  |
| `Ctrl+F`            | 当前会话内消息搜索（含已压缩的「更早的对话」；Enter/Shift+Enter 上下一个匹配，Esc 关闭）                                      |
| `Ctrl+,`            | 打开设置                                                                                                                      |
| `Esc`               | 关闭弹窗 / 收起菜单；**智能体运行中且焦点不在输入框时 = 停止本轮生成**                                                        |
| `Ctrl+=` / `Ctrl+-` | 窗口缩放 ±25%                                                                                                                 |
| `Ctrl+0`            | 窗口缩放恢复 100%                                                                                                             |

| ------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |

## 23. 常见问题

**模型选择器显示「无可用模型」**
回到「设置 → 模型与提供商」确认已保存；逐项检查 API Key、Base URL（注意 `/v1`）、API 类型、模型 ID，用「测试可用性」定位问题。仍不行时重开一次会话。

**思考等级里没有 `max`（或某档位缺失）**
确认模型卡片打开了「思考」，且 `thinkingLevelMap` 没有把该档位设为隐藏；即使设置里可见，服务商实时返回的能力列表不支持的档位也不会显示。

**新会话没出现在项目下**
会话通常在第一条消息发送后才持久化。先发一条任务，等 Pi 开始回复或完成后再看左侧列表。

**文件 tab 显示的不是当前项目**
文件树跟随当前会话的项目文件夹。先切到目标会话，再看「文件」tab。

**生成了内容但预览没更新 / 没有文件产物**
确认聊天中的文件产物路径与当前项目一致；若 Pi 只把 Markdown 贴在聊天里没写文件，继续发送「请把刚才的内容实际写入 docs/result.md」。外部程序修改的文件重新打开预览即可。

**发送失败后输入不见了？**
不会。任何发送失败都会把文本/图片/附件完整恢复到输入框并弹错误提示（见 6.5）。若看到会话里出现无响应的用户气泡，说明是旧版本行为，升级到最新版即可。

**会话突然无法继续、报 provider 拒绝历史**
看输入框上方是否出现红色「一键修复」横幅；有则点击修复（自动备份原文件），没有则把报错信息反馈给维护者。

**交接新对话一直转圈 / 新会话没生成**
交接要看起来跑一轮模型（生成交接文档），几十秒是正常的，按钮会显示「交接进行中…」。超过一两分钟仍无反应，看当前会话是否上下文过满（先压缩），或模型服务是否不可达（看报错横幅）；它不会损伤原会话。只想快点开个空白会话，就用长按 / 右键那个「原地新建」。

**列表里的会话显示「已回收」**
正常行为：闲置 2 小时后进程被停掉省内存，点开自动重启，历史与草稿都在。

**凭据存不进去**
名称必须 2–64 位、只允许小写字母 / 数字 / `._-`；值不能为空。提示「本机加密不可用」说明系统级加密在当前环境不可用（如某些精简系统 / 无登录密钥环），MPI 会**拒绝保存**而不是退化成明文——这是有意设计。

**升级/重装后任务栏图标还是旧的**
Windows 按路径缓存图标，MPI 已用内容哈希绕开该问题。完整重启一次应用即可看到新图标。

**扩展包安装报 `spawn npm ENOENT` / git 相关错误**
旧版本才可能出现：现在 MPI 内置 npm，未装 Node.js 也能安装；git 源安装需要系统装有 Git（缺失时会有明确提示）。若你手动改过 `settings.json` 的 `npmCommand`，请确认该命令可用。

**dev 版和正式版数据会混吗？**
不会。两者配置目录独立（`MPI Dev` / `MPI`），但共享同一个 `~/.pi/agent`；模型、扩展、会话历史是共用的，这正是设计意图。
