## 1. 认识 MPI

MPI 是 [Pi coding agent](https://github.com/earendil-works/pi) 的独立桌面客户端（Pi Studio 的个人 fork，与 Pi 维护者没有隶属或官方背书关系）。它把项目、会话、模型配置、扩展、权限控制、定时任务、待办任务和文件预览整合到同一个桌面工作区中。

几个关键概念：

| 概念 | 说明 |
| --- | --- |
| **项目** | 一个本地文件夹。Pi 在该项目目录内读取代码、创建文件并执行操作。 |
| **会话（Session）** | 一次与智能体的连续对话，对应一个会话文件。同一项目下可以有多个会话。 |
| **权限模式** | 控制 Pi 可以自动执行哪些操作的档位：只读 / 严格 / 沙盒 / 完全。 |
| **扩展功能** | pi 的技能（skill）、扩展包（npm/git/本地）和 MCP 服务器，统一在「扩展功能」面板管理。 |

与终端 pi 的关系：MPI 与命令行 pi **共享同一个 agent 配置目录 `~/.pi/agent`**——模型、API Key、扩展、技能、MCP 配置两边通用；在终端里装的扩展，桌面端直接可用，反之亦然。会话文件也存放在该目录下，因此终端和桌面端可以看到同一批会话历史。

每个安装包都内置了固定版本的 Node.js + Pi 运行时（`MPI-Runtime-*.tar.gz`），**不需要单独安装 Node.js**。首次启动时 MPI 会校验并把内置运行时解压到用户数据目录；之后的应用更新复用已解压的运行时，无需重新下载。

## 2. 安装与首次启动

### 2.1 安装包

| 平台 | 文件 | 说明 |
| --- | --- | --- |
| Windows x64 | `MPI-Setup-<version>.exe` | NSIS 安装程序，双击运行。 |
| macOS（Apple Silicon） | `MPI-<version>-arm64.dmg` | 拖拽安装。 |

当前安装包**尚未代码签名**，首次运行时系统可能弹出安全提示——属正常现象，确认来源可信后继续即可。

### 2.2 Windows 安装步骤

1. 双击 `MPI-Setup-x.y.z.exe` 启动安装向导。
2. 若 SmartScreen 提示「Windows 已保护你的电脑」：点**更多信息 → 仍要运行**。
3. 按向导提示完成安装（默认安装路径即可）。
4. 从桌面快捷方式或开始菜单启动 MPI。

### 2.3 macOS 安装步骤

1. 双击 `MPI-x.y.z-arm64.dmg`，把 MPI 图标拖入「应用程序」文件夹。
2. 首次启动时 Gatekeeper 可能拦截：在「应用程序」中**右键点 MPI → 打开**，在弹窗中确认；或到「系统设置 → 隐私与安全性」里允许一次。

### 2.4 校验安装包（可选）

若安装包旁附带了同名的 `.exe.sha256` 文件，可先校验完整性：PowerShell 执行 `Get-FileHash .\MPI-Setup-x.y.z.exe -Algorithm SHA256`，将输出与 sidecar 文件内容逐字符比对。应用内也可查看校验步骤：**设置 → 应用更新 → 查看更新日志**（弹窗底部附「安装校验方法」）。

### 2.5 首次启动

1. 启动 MPI；首次启动会解压内置运行时，稍等片刻即可进入主界面。
2. 打开 **设置 → 模型与提供商**，添加你的第一个模型（见[第 4 节](#4-配置模型)）。
3. 在左侧「项目」旁点 `+` 打开一个本地文件夹作为项目。
4. 点击「新建会话」，发送第一条消息。

### 2.6 开机自启动

**设置 → 通用设置 → 开机自启动**。勾选后 MPI 会在登录系统时自动运行（Windows 下在开始菜单的启动文件夹创建快捷方式）。取消勾选即移除。

## 3. 界面总览

MPI 主窗口分为四个区域：

```
┌────────────────────────────────────────────────────────────┐
│ 标题栏：品牌 · 文件/编辑/视图/帮助 菜单 · 状态文字 · ⚙设置   │
├──────────┬─────────────────────────────────┬───────────────┤
│ 导航栏    │ 会话区（聊天 / TUI 终端）         │ 预览区          │
│ (左)     │ (中)                            │ (右，可开关)    │
│ · 项目    │ · 顶栏：标题/文件夹/操作按钮      │ · Markdown/HTML │
│ · 会话    │ · 消息列表 + 工具卡片            │   /代码/图片…   │
│ · 文件    │ · 输入框（附件/命令/权限/模型）   │                 │
└──────────┴─────────────────────────────────┴───────────────┘
```

### 3.1 标题栏

- **左侧菜单**：
  - `文件`：新建会话、打开文件夹…
  - `编辑`：复制 / 剪切 / 粘贴 / 删除、进入设置…
  - `视图`：折叠/展开导航栏、切换预览面板
  - `帮助`：关于 MPI
- **中间**：状态文字（当前会话名 · 模型，或「Pi 已就绪」）。
- **右侧**：⚙ 打开设置；最小化 / 最大化 / 关闭窗口。

### 3.2 导航栏（左侧）

从上到下：

1. **顶部按钮行**：🔍 全局搜索（等同 Ctrl+K）、折叠导航栏。
2. **快捷入口**：「新建会话」「定时任务」（时钟图标）、「待办任务」（方框对勾图标）、「扩展功能」（插头图标）四个带文字的按钮，分别打开新会话、[定时任务面板](#10-定时任务)、[待办任务面板](#11-待办任务)、[扩展功能面板](#12-扩展功能技能--扩展包--mcp)。
3. **标签页**：`会话` / `文件`。
   - 「会话」tab：项目列表 + 各项目的会话列表。
   - 「文件」tab：当前会话所在项目的文件树，点击任意文件在预览区打开；**文件行可以直接拖到输入框作为附件**（目录不可拖）。
4. **项目区**：
   - `+` 按钮：打开文件夹（新建/选择项目）。
   - 每个项目行：名称、会话数徽标、`+`（在该项目下新建会话）、星形置顶按钮。
   - 右键项目：**上移 / 下移**（仅置顶项）、在资源管理器中打开、置顶/取消置顶项目、归档项目。
5. **会话区**：
   - 顶部是**置顶区**，下面是按活跃时间排序的最近会话。
   - 每条会话行右侧有**常驻星形按钮**（空心=未置顶，点亮=已置顶），点击即切换；悬停时还出现归档、删除图标。
   - 右键会话：**上移 / 下移**（仅置顶项）、置顶/取消置顶会话、克隆会话、删除。
   - **拖拽排序**：在置顶区内拖动换序；把最近区的条目拖进置顶区 = 在该位置置顶；把置顶条目拖出到末尾 = 取消置顶。
6. **底部用量行**：常驻显示「今日用量 · 总用量」（token 数，k/M 紧凑格式）。悬停查看今日/合计明细、花费与会话总数；流式结束后自动刷新，每 60 秒轮询一次（终端 pi 的活动也会计入）。

导航栏宽度可以拖动右边缘调整，双击恢复默认。

### 3.3 会话区（中间）

**顶栏**：

- 左侧：会话标题（**双击重命名**）、工作文件夹路径（悬停显示完整路径，点击在资源管理器中打开）、连接状态提示。
- 右侧按钮（从左到右）：⭐ 置顶/取消置顶当前会话、✎ 重命名、📁 切换工作文件夹、＋ 新建会话（在当前上下文中开一段新对话）、⌨ **终端**（切换到 Pi TUI，见[第 13 节](#13-pi-tui-终端模式)）、👁 切换预览。

**消息列表**：

- 用户消息在右侧（默认头像「大雄」），智能体回复在左侧（默认头像「哆啦A梦」）；头像可在设置中自定义。
- **工具卡片**：Pi 每次调用工具（读文件、执行命令、编辑等）都会生成一张卡片，可展开查看参数与结果。`edit` 类工具的 diff 会**自动展开**为 git 风格单栏视图（上下文行 + `-`/`+` 着色行），多处替换时标题条显示「N 处替换」徽标；手动收起后不再强制打开。
- **文件产物 chip**：Pi 写入/修改的文件会以 chip 形式出现在消息下方，点击在预览区打开。
- **圆点导航**：用户消息 ≥2 条时，聊天区左侧出现竖排圆点，悬停显示该条消息预览，点击跳转。
- **跳转到最新消息**：向上滚动离开底部后，右下角出现圆形双箭头浮动按钮，点击平滑滚回最新。
- 流式输出期间自动贴底跟随；手动上滚阅读时不被拉回，滚回底部附近恢复跟随，每轮结束后平滑回到最下方。

**输入框（Composer）**，从左到右：

| 控件 | 作用 |
| --- | --- |
| `+` | 添加文件/图片附件 |
| `/ 命令` | 打开斜杠命令菜单（内置命令、扩展命令与技能） |
| 权限 pill | 切换当前会话的权限模式（四档，见[第 7 节](#7-权限模式)） |
| 圆环按钮 | 上下文用量进度环 + 详情浮层（见[第 8 节](#8-上下文管理)） |
| 模型 pill | 选择提供商 / 模型 / 思考等级，以及「会话工具」（完成提示音开关） |
| 发送 / 停止 | 发送消息；智能体运行中变为「停止」按钮 |

输入框上方会显示当前工作文件夹（可点击切换项目）。未发送的输入（文本、图片、附件）**按会话自动保存草稿**，重启应用后重新打开该会话时恢复。

### 3.4 预览区（右侧）

在聊天顶栏点「切换预览」（或视图菜单）开关。支持 Markdown、HTML、源代码、图片和常见办公文档的渲染/高亮显示，详见[第 9 节](#9-文件预览与-html-元素引用)。

## 4. 配置模型

MPI 通过 Pi 共享的 `models.json`（位于 `~/.pi/agent`）管理提供商和模型，与终端 pi 完全通用。

### 4.1 添加提供商

**设置 → 模型与提供商**页面分两段：上方是**预设供应商**，下方是**我的供应商**。

- **预设快速接入**：上段以卡片列出常用平台（阿里云百炼 API 按量付费 / Coding Plan、智谱、DeepSeek、Kimi / Moonshot、Gemini、GPT / OpenAI），另有「自定义配置」「本地部署」两个入口（LM Studio、Ollama 等自托管服务从这里进）。点击平台卡片会打开预填好地址、API 类型和首个模型的新增表单，补上 API Key（按需微调）即可添加；已配置过的平台卡片带绿色描边，若它还是当前默认提供商则显示「当前」徽标——此时点击直接展开下段对应供应商的编辑器。顶部搜索框可按名称过滤平台，「刷新预设」重新读取 models.json 更新各平台的配置状态。
- **自定义配置 / 本地部署**：打开空白（或预填 Ollama 默认地址）的新增表单，接入任意 API：

| 字段 | 填写说明 |
| --- | --- |
| 提供商名称 | 自定义名称，例如 `deepseek`、`openai`、`my-provider`。 |
| API 类型 | 按服务商文档选择 `openai-completions` / `openai-responses` / `anthropic-messages` / `google-generative-ai`。兼容 OpenAI 的服务通常选 OpenAI 兼容类型，但以服务商文档为准。 |
| API 地址 | Base URL，例如 `https://api.example.com/v1`（注意 `/v1` 路径）。 |
| API Key | 直接填密钥，或写环境变量引用如 `$MY_API_KEY`。**不要把真实密钥写进截图、提交记录或共享文档。** |
| 模型 ID | 服务商真正使用的模型 ID；可留空，稍后在供应商编辑器里补。 |

填写后点「添加供应商」，再点「保存模型配置」。模型随即出现在输入框的模型选择器中。

- **我的供应商**：下段每个已配置的供应商显示为紧凑卡片（名称 + 模型数 + 地址），点击即在下方展开完整编辑器——基础地址、API 类型、API Key、请求头、compat 高级 JSON，以及逐模型的设置；重命名或删除供应商也在这里进行。

### 4.2 模型卡片设置

每个模型一张卡片，常用选项：

- **思考**：打开后 MPI 会向该模型请求思考档位（关闭则不显示思考等级）。
- **图像**：模型支持图片输入时勾选。
- **上下文长度 / 最大输出**：按服务商文档填写 token 数。
- **测试可用性**：一键检查 Base URL、API Key、模型 ID 是否可正常调用。

高级设置（展开卡片右侧）：

- `compat`：仅在服务商有特殊兼容要求时修改，必须保持合法 JSON。
- `thinkingLevelMap`：把 Pi 的标准思考档位逐项映射到服务商档位，不需要手写 JSON。每个档位可选「未指定」（用服务商默认）、「隐藏该档位」或具体标准档位 / 自定义值。

### 4.3 思考等级

Pi 的标准思考档位为 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`（界面显示「关/最低/低/中/高/超高/最高」）。在模型选择弹层里，「思考等级」是一行标签 + 胶囊按钮，点击展开圆角选项列表；若配置了映射，选项会带提示如 `中 → mid`。

注意：实际可选档位还受模型实时能力列表影响——服务商没声明的档位不会出现在当前会话的选择器中。

### 4.4 思考默认值

**设置 → 思考默认值**：

- **默认思考深度**、**默认提供商 / 默认模型**：新会话的初始选择（进入会话后仍可随时切换）。
- **隐藏思考块**：打开后回复中的思考内容不显示。

### 4.5 配置不生效时排查

1. 打开 **设置 → 诊断与配置**，查看 `models.json`、`settings.json`、`auth.json` 的实际路径，确认改的是对的文件。
2. 常见原因：模型 ID 拼错；Base URL 多/少 `/v1`；API 类型与协议不匹配；Key 无权限；模型没开「思考」所以没有档位。

### 4.6 用户画像

**设置 → 用户画像**：写一段简短的自我介绍和偏好——你是谁、技术栈、希望回复怎么组织（例如“简洁、先说结论”）。这段文字会附加到每个会话的系统提示词里，AI 从第一条消息起就了解你的背景。

- 最多 4000 字；清空后保存 = 关闭注入。
- 对**新会话**生效；已打开的会话重连后生效（关闭再打开即重连）。定时任务同样使用这份画像。
- 存于 MPI 应用配置目录（`config.json`），不影响终端 pi。

## 5. 项目与会话管理

### 5.1 打开项目

- 导航栏「项目」标题旁的 `+`，选择（或新建）一个本地文件夹。
- 空状态页的「打开项目文件夹」按钮。
- 菜单：文件 → 打开文件夹…

选中的文件夹成为当前项目并出现在左侧列表；项目名称旁的数字是该项目下已发现的会话数。

### 5.2 新建会话

三个入口，效果相同（在当前/指定项目下开一个空白会话）：

1. 导航栏顶部「新建会话」按钮（无项目时会先让你选文件夹）。
2. 某个项目行右侧的 `+`。
3. 菜单：文件 → 新建会话。

尚未发送第一条消息的草稿会话，可以通过聊天顶栏的「切换工作文件夹」换到别的项目。

### 5.3 重命名 / 置顶 / 排序

- **重命名**：双击会话标题，或点顶栏 ✎ 按钮。
- **置顶**：三种等效方式——会话行上的常驻星形按钮、聊天顶栏的 ⭐ 按钮、右键菜单「置顶会话」。新置顶排在置顶区末尾。
- **排序**（仅置顶项）：右键「上移 / 下移」，或在置顶区内直接拖拽；顺序重启后保留。最近区始终按活跃时间自动排序。

### 5.4 分支与克隆

| 操作 | 入口 | 行为 |
| --- | --- | --- |
| **分支（Fork）** | 悬停任意一条**用户消息** → 「分支」按钮 | 从该条提问**之前**分叉出一个新会话，并把被分叉提问的原文自动填入输入框（可修改后发送）。原会话标记为已断开。与 TUI `/fork` 行为一致。 |
| **克隆（Clone）** | 侧栏右键会话 → 「克隆会话」 | 把当前活跃分支**完整复制**成一个新会话文件，包含全部历史。 |

流式回复进行中点分支/克隆会提示等待结束。

### 5.5 归档与删除

- **归档会话**：悬停会话行点归档图标（或右键）。归档后会话从导航栏和默认搜索中消失，可在「设置 → 归档回收」或 Ctrl+K（勾选「归档回收」）里找到并一键恢复。
- **归档项目**：右键项目 → 「归档项目」。整个项目的会话一起归档，恢复方式相同。
- **删除会话**：悬停点垃圾桶图标或右键「删除」。默认先移入**回收站**（可恢复），只有从回收站里再删才算永久删除；在「设置 → 通用设置」关闭回收站开关后，删除立即永久生效。详见[第 15 节](#15-归档与回收站)。

### 5.6 会话的其它行为

- **新建会话（顶栏 ＋）**：在当前工作上下文中开一段新对话（同一项目、同一权限设置）。
- **重启恢复**：退出 MPI 前停留在哪个会话，重新打开就自动进入该会话；若该会话已被归档/删除则静默跳过。
- **优雅停机**：关闭会话或退出应用时若有进行中的任务，MPI 会先中止并等待落盘（上限数秒），避免损坏会话文件。

## 6. 与智能体对话

### 6.1 基本输入

- **Enter** 发送；**Shift+Enter** 换行。
- 中文/日文输入法组词期间按回车确认候选词**不会**误发消息。
- 写清楚四件事效果更好：要完成什么、目标文件/目录在哪、输出格式与限制、完成后如何验证。

### 6.2 附件

三种方式，效果相同（出现在输入框上方附件列表，随消息发送）：

1. 点 `+` 按钮选择文件；
2. **从导航栏「文件」tab 把文件行直接拖进输入框**（拖悬时输入框出现高亮描边；同一文件重复拖入不会重复添加；目录不可拖）；
3. 从系统资源管理器拖文件进来，或直接粘贴图片。

### 6.3 斜杠命令与技能

点 `/ 命令` 按钮或在输入框敲 `/` 打开菜单（内置命令、扩展命令与技能三类）。常用：

- `/compact [说明]`：手动压缩上下文，可附压缩侧重点说明（等同上下文浮层里的压缩图标）。
- `/skill:名称 [参数]`：显式调用某个已安装的技能。
- 扩展包自带的斜杠命令也会出现在这里。

### 6.4 运行中追加指令

智能体正在回复时，输入框的发送按钮变为「停止」，同时支持两种追加方式（悬停发送按钮可见提示）：

- **Enter**：存为**待处理后续**——排队等当前轮结束后再执行；
- **Alt+Enter**：**立即插入上下文执行**（steer），尽快影响正在进行的任务。

已排队的消息显示在输入框上方，可「重新编辑」或点按钮立即执行。

### 6.5 草稿与发送失败保护

- 未发送的文本/图片/附件按会话落盘保存（最近 40 份），重启后自动恢复；发送成功、或删除到最后一个字符时清除。
- **任何发送失败**（连接失败、RPC 报错等）都会：回滚已显示的用户气泡、把原文本/图片/附件完整恢复到输入框、弹错误提示——不会丢输入，也不会留下无响应的「幽灵消息」。

### 6.6 消息上的操作

- 悬停**用户消息**：复制这条消息 / 分支（见 5.4）。
- 智能体回复下方：复制、有帮助/没帮助反馈。
- 「完成提示音」开关在模型选择弹层的「会话工具」里——智能体完成任务时播放一声短促提示音，可关闭。

## 7. 权限模式

MPI 用**权限门**控制 Pi 执行 shell 命令、写文件和扩展操作的行为。每个会话独立设置，输入框左侧的权限 pill 可随时切换（即时生效，无需重启会话）。

| 档位 | 行为 | 适用场景 |
| --- | --- | --- |
| **只读** | 只读操作可执行；任何修改类操作**直接阻止**且不弹确认。 | 纯问答、代码分析，绝不想让 Pi 动文件。 |
| **严格** | 只读命令自动执行；所有写入/删除/修改类命令都需确认。对 write/edit 工具可选「本线程允许该工具」避免反复弹窗。 | 需要频繁改文件但想逐条把关。 |
| **沙盒（默认）** | 项目内低风险操作（如 `npm run build`）自动执行；危险命令、写项目外位置等弹确认框。 | 日常开发，推荐默认值。 |
| **完全** | 不拦截任何操作。 | 明确信任的任务/环境。 |

- **新建会话默认权限**：设置 → 通用设置里的下拉框（只读/严格/沙盒/完全），控制之后新建会话的初始档位；已有会话保留各自设置。
- **确认弹窗**：需要授权时弹出「权限确认 / Permission required」，显示具体命令与目标路径，检查后再决定允许或拒绝。新手建议先看清命令和目标位置再放行。
- 定时任务无法等待人工授权，因此只提供**沙盒 / 完全权限**两档（见[第 10 节](#10-定时任务)）。

> 提示：权限门能显著减少误操作，但不能替代操作系统级隔离；对不信任的代码环境请配合系统沙箱使用。

## 8. 上下文管理

### 8.1 用量圆环

输入框底栏（模型选择器左侧）的**圆环按钮**实时显示当前会话的上下文占用：弧线 = 占比，颜色分四档——≤60% 绿 / 60–74% 黄 / 75–89% 橙 / ≥90% 红。切换会话时加载、流式结束/压缩完成即时刷新、运行中每 15 秒轮询。

### 8.2 上下文窗口浮层

点开圆环查看：当前模型名、进度条、「~已用 / 总量 + 百分比」、**「已压缩 N 次」**（悬停显示最近一次时间）、按占用档位着色的压缩建议，以及右上角的刷新与**压缩图标**。

- ≤60%：暂无需压缩
- 60–74%：长任务可提前压缩
- 75–89%：建议手动压缩留出空间
- ≥90%：强烈建议立即压缩
- 累计压缩 ≥3 次时追加提醒：早期细节可能丢失，重要结论建议写入文件或记忆。

### 8.3 压缩上下文

三种触发方式：

1. 浮层右上角的压缩图标（等同 `/compact`）；
2. 输入框敲 `/compact [说明]`；
3. 长对话达到阈值时 pi **自动压缩**（失败会弹警告提示）。

压缩后 token 数显示为估算值（带 `~` 前缀），直到下次回复拿到真实数字。

### 8.4 砖会话一键修复

极少数情况下 provider 会因「空白 tool result」或「孤儿 tool_result」拒绝整个会话历史，导致无法继续对话。此时输入框上方出现红色横幅与**「一键修复并重新加载」**按钮：MPI 对会话 JSONL 做手术（占位替换/清理过期压缩记录），修改前自动备份到 `sessions/mpi-repair-backups/`，幂等且原子写回，完成后自动重开会话。

## 9. 文件预览与 HTML 元素引用

### 9.1 打开文件

- 导航栏「文件」tab 点击任意文件；
- 聊天消息里的**文件产物 chip** 点击；
- 附件 chip 点击（在 MPI 中查看）。

### 9.2 支持的类型

| 类型 | 行为 |
| --- | --- |
| Markdown | 完整渲染标题、列表、表格、代码块、图片。 |
| HTML | **实时预览**（沙箱 iframe），支持缩放（50%–200%，滚轮/按钮）。 |
| 源代码 | 语法高亮 + 行号。 |
| 图片 | 点击放大灯箱查看。 |
| 办公文档等 | 尽力渲染，复杂格式建议用系统默认程序打开。 |

### 9.3 预览标题栏按钮（从左到右）

- **在资源管理器中显示**：定位并选中该文件（文件不存在会报错提示）。
- **刷新预览**：重新读取文件内容。
- **展开 / 收缩**：让预览占据主工作区，或恢复侧边布局。
- **关闭**。

左侧边缘可拖动调整预览宽度，双击恢复默认。

### 9.4 HTML 元素引用（标注模式）

预览 HTML 文件时，标题栏会出现「选择 HTML 元素并引用到输入框」按钮：

1. 点击开启**标注模式**，鼠标悬停高亮、点击选中页面上的任意元素；
2. 选中的元素信息（CSS selector、标签名、文本、当前样式、HTML 片段）作为一张 **HTML 引用卡片**自动加入输入框附件区——发送后 Pi 能精确知道你在指哪个元素，适合「把这个按钮改成红色」这类需求；
3. 标注模式下还有**编辑按钮**：选中元素后可直接修改其内容并写回 HTML 源文件（状态条显示「点击元素 / 编辑中」）；
4. 引用卡片可展开查看详情、可移除。

## 10. 定时任务

导航栏的时钟图标打开「定时任务」面板。**仅在 MPI 运行时调度**——应用关闭期间不会执行。

### 10.1 新建任务

点 `+`，填写：

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 例如「每日晨报」。 |
| 工作文件夹 | 任务运行的项目目录（Pi 在该目录下工作）。 |
| 提示词 | 到点要执行的完整指令；可以使用已安装的技能。 |
| 重复 | **每小时**（第 N 分钟）/ **每天**（HH:mm）/ **每周**（勾选星期 + HH:mm）。 |
| 运行权限 | **沙盒**（默认，需要确认的操作会被阻止）或 **完全权限**。定时任务无法等待人工授权，请只给明确信任的任务开完全权限。 |

### 10.2 管理任务

- 每行显示名称、调度摘要、上次状态（失败会标红并悬停显示原因）、启用开关；
- 「立即运行」按钮手动触发一次；「编辑」修改后保存；删除带确认。
- 任务执行结果以独立会话出现在对应项目下，会话名前缀为「定时任务: xxx」（旧版创建的「自动化: xxx」仍会被识别并随语言本地化）。完成/失败会弹 toast 通知。

## 11. 待办任务

导航栏的方框对勾图标打开「待办任务」面板。待办**按项目记录**，支持截止日期、备注与智能日期解析；智能体也可以在对话中直接添加待办（带 AI 标记）。

### 11.1 添加待办

- 在面板顶部输入框直接输入文字回车即创建。左侧选中「全部项目」时，先用下拉框选择目标项目；选中某个具体项目后，新待办自动归属该项目。
- **智能日期解析**：可以在文字里直接写日期——`明天发周报` → 标题「发周报」、截止明天；也支持 `周五`、`9月30日`、`12-5` 等写法；识别不到日期则作为无日期待办。
- 点击某一行展开行内编辑器：可修改标题 / 备注 / 截止日期（或清除日期）后保存，也可以直接删除（不弹确认框）。

### 11.2 智能分栏

面板按时间维度分组，每个 chip 显示数量：**全部** / **今天**（含已过期，过期标红）/ **明天** / **本周**（周一至周日）/ **稍后**（本周五之后的日期）/ **无日期** / **已完成**。在「已完成」分栏底部可点「清空已完成」批量删除当前范围内的已完成项。

### 11.3 项目范围与智能体协作

- 左侧列选择某个项目即只看该项目的待办；「全部项目」显示所有项目的待办，行上带项目名标签。
- 智能体在对话中调用 `mpi_todo_add` / `mpi_todo_list` 工具时，会通过收件箱机制写入本面板（主进程监听并去重入库）；这类行右侧有 **AI** 徽标，点击直接跳转到来源会话。
- 数据存于 `%APPDATA%\MPI\todos.json`（见[第 20 节](#20-数据与配置位置)），dev 版与正式版相互独立。

## 12. 扩展功能：技能 / 扩展包 / MCP

导航栏的插头图标打开「扩展功能」面板（管理 pi 的扩展包与技能），顶层三个模块 tab：**技能 N / 扩展包 M / MCP K**（各带计数）。

### 11.1 技能（Skill）

技能是 `SKILL.md` 形式的指令集，pi 在合适时机自动加载，也可用 `/skill:名称` 显式调用。三个子 tab：

- **我的技能**（主从布局）：左列搜索 + 全部/已启用/已禁用过滤 + 按来源目录分组列表；右列详情栏——徽章、「复制命令」（把 `/skill:name` 写入剪贴板）、启用/停用开关、SKILL.MD 渲染预览与「复制 Markdown」。
- **Skill 市场**：浏览搜索 [skills.sh](https://skills.sh/) 公开目录并一键安装到 Pi；搜索框上方固定横条提供其他市场外链（虾评 / SkillHub / SkillsMP）。
- **统计**：总数/已启用/已禁用统计卡、按来源目录分布条、已禁用技能列表（可一键重新启用）。

### 11.2 扩展包（Extension）

pi extension 是 npm/git/本地路径安装的代码扩展，可为 pi 增加工具、命令与 UI。两个子 tab：

- **我的扩展包**：顶行「＋安装扩展包 / 更新全部」；点 ＋ 展开内联输入框（支持 `npm:<包名>`、`git:` 地址或本地路径，Enter 安装）。左列按 npm/git/local 分组列表 + 右列详情栏（类型/版本徽章、来源与安装目录、package.json 说明、更新/启用停用/移除按钮）。
- **扩展包市场**：搜索公共 npm registry（默认查询 “pi extension”，前 30 条按相关度排序）；左列结果列表 + 右列详情栏（版本/license/周下载徽章、npm 页面与仓库链接、README 预览），一键安装走 `npm:<包名>`。

> 扩展包安装使用 MPI **内置的 npm**，未安装 Node.js 的电脑也能装；从 git 源安装需要系统装有 Git（缺失时会给出明确提示）。若你手动配置过 `~/.pi/agent/settings.json` 里的 `npmCommand`，MPI 不会覆盖它。

### 11.3 MCP

MCP（Model Context Protocol）服务器为 pi 提供外部工具与数据源。两个子 tab：

- **我的 MCP**：顶部依赖条显示 `pi-mcp-market` / `pi-mcp-adapter` 扩展的启用状态（缺失可一键补装）。左列列出 `~/.pi/agent/mcp.json` 中已配置的服务器（stdio/remote 徽章）；右列详情栏——命令复制、启用/停用开关（只写 disabled 标志，可随时恢复）、删除（带确认）。
- **MCP 市场**：浏览 mcpmarket.cn 公开目录（logo/作者/stars/简介），支持关键词搜索与「加载更多」；点卡片查看中英文 overview 分节与 GitHub 链接。

> MCP 模块依赖 `pi-mcp-market` 扩展，未安装时显示不可用卡片 + 一键安装按钮；实际连接与运行服务器还需 `pi-mcp-adapter`。

## 13. Pi TUI 终端模式

聊天顶栏的「**终端**」按钮把整个会话区切换成交互式 pi 终端（xterm.js）：

- 与 GUI 模式**共用同一会话文件与工作目录**，历史双向共享——在终端里发的消息切回 GUI 后照样可见；
- 进入 TUI 前若正在回复会先自动中止；
- 退出方式：再点一次「终端」按钮、在终端里 `/exit`、或切换到别的会话（自动结束终端进程）；
- 窗口缩放时终端尺寸跟随。

适合习惯键盘流、想直接用 pi 全部 TUI 命令的用户。

## 15. 归档与回收站

**设置 → 归档回收**页统一管理三类条目，均按项目分组（组头显示项目名 + 计数，可折叠），顶部搜索框同时过滤三类（标题/项目名/路径子串匹配）：

| 区块 | 内容 | 操作 |
| --- | --- | --- |
| 已归档项目 | 整个被归档的项目 | 恢复项目。 |
| 已归档会话 | 单个归档的会话（显示归档时间，悬停可见完整文件路径） | 恢复到原项目。 |
| 回收站 | 删除的会话（默认开启；显示删除时间 + 占用大小），头部可「清空回收站」（带确认） | 「恢复会话」回到原项目 / 「永久删除」（带确认）。 |

规则：

- **归档**是可逆的整理手段，不影响文件本身；
- **删除**默认先进回收站（`<userData>/trash/`），只有从回收站里再删才算永久删除；在「设置 → 通用设置」关闭回收站开关后，删除立即永久生效（已入站的条目仍可恢复/清空）。

| **Diff 显示** | edit 工具 diff 的「统一视图 / 前后分块」两种模式，默认统一。 |
| **窗口缩放** | 50%–150%，快捷键 Ctrl+= / Ctrl+-（25% 步进）、Ctrl+0 恢复；重启后保持。 |

### 15.4 备份与恢复

两个相互独立的备份对象，各自有导出/导入一对按钮：

**应用设置**：把 MPI 的应用配置（`config.json`：主题、语言、置顶、头像、用户画像、定时任务、远程信令等）导出为单个 JSON 文件（默认名 `mpi-config-backup-<日期>.json`）。导入时先显示可识别的设置项数量并要求确认，确认后只覆盖备份里包含的对应项（其余设置保持不变）。模型提供商/思考默认值存于 `~/.pi/agent`（与终端 pi 共享），不在本备份范围内；机器相关项（pi 路径、窗口位置）导入时永不恢复。

**会话**：勾选要导出的项目（可全选/清空，显示每个项目的会话数与占用大小），把所选会话的原始 JSONL 文件打包为 zip（`mpi-sessions-backup-<日期>.zip`，保留项目目录结构）。导入时先提示「N 个新会话 / M 个已存在」：默认只导入新的、跳过已存在的文件；如需以备份为准恢复，选「覆盖全部」。导入后会话回到原属项目（导航栏自动刷新）。

典型用途：换新电脑迁移、大改动前留快照。

### 15.5 诊断与配置

显示 Pi 运行时状态、各配置文件（`models.json` / `settings.json` / `auth.json`）的实际路径，可点击在资源管理器中打开。模型/思考设置写入 `~/.pi/agent`（与终端 pi 共享），通用设置存于应用配置目录——排查「改了不生效」时先看这里。

- **MPI 应用更新**：当前版本 / 最新版本、来源（GitHub Releases）、「查看更新日志」（随包内置 changelog，无需联网；底部附 SHA256 安装校验方法）、发现新版本后「安装并重启」。

## 17. Android 手机远程控制

> **当前状态**：该功能的界面入口在最新版本中暂时隐藏（待优化后恢复），以下为其设计能力说明，供参考。

MPI 支持通过 Android companion 应用远程查看会话并执行经过批准的控制操作：

- **配对**：桌面端生成含短期票据的二维码（5 分钟失效）；手机扫码或粘贴 `mpi://pair?...` 链接完成配对，桌面端「待批准设备」里允许/拒绝。
- **传输**：WSS 信令 + STUN 直连 WebRTC。**信令服务不接收提示词、代码、会话或文件内容**；TURN/relay 候选被有意拒绝（只走 P2P 直连）。
- **管理**：查看信令连接状态、已信任设备列表，可随时撤销设备。

## 18. 消息接入（飞书）

在飞书里给机器人发消息，就能驱动 MPI：私聊或群里 @它，消息会进入绑定项目下的专属会话执行，agent 的回复流式更新回同一条消息。该功能仅在 **MPI 运行期间**在线。

### 17.1 启用渠道

打开 **导航栏 → 消息接入**（「新建会话 / 定时任务 / 扩展功能」下方第四项）。面板左列为通道列表，选择 **飞书**（微信即将支持），在右侧填写：

| 字段 | 说明 |
| --- | --- |
| 启用飞书接入 | 总开关；关闭时不建立任何连接 |
| App ID / App Secret | 飞书开放平台自建应用的凭证（Secret 只保存在本机，保存后不再回显） |
| 绑定项目 | 消息执行所在的项目文件夹；其下会自动创建名为「飞书接入」的专属会话 |
| 会话权限 | 沙盒（默认，阻止需要确认的操作）/ 完全权限 |

点 **保存配置** 立即生效。面板顶部状态灯：灰 = 未启用、黄闪 = 连接中/重连中、绿 = 已连接、红 = 失败（下方显示错误详情）。

### 17.2 创建飞书应用（首次使用）

> ⚠️ **前提：必须有企业/组织。** 飞书开放平台要求自建应用挂在**企业租户**下，且长连接事件推送仅支持企业自建应用。如果你的账号是个人版（没有企业），请先免费创建一个自己的企业（个人可自建，无需营业执照，创建后你就是管理员）——否则会出现「能连上但永远收不到消息、后台找不到发布入口」的现象。

1. 登录 [open.feishu.cn/app](https://open.feishu.cn/app)（没有企业先按上面提示创建一个）；
2. 创建**企业自建应用**，在「凭证与基础信息」记下 App ID 和 App Secret；
3. 「应用能力 → 机器人」添加**机器人能力**；
4. 「权限管理」开通：`im:message.p2p_msg:readonly`（接收单聊消息）、`im:message.group_at_msg:readonly`（接收群聊 @机器人 消息）、`im:message:send_as_bot`（以应用身份发消息）；
5. 「事件与回调」选择**使用长连接接收事件**，并添加事件 `im.message.receive_v1`（接收消息 v2.0）；
6. 创建版本并发布（或先设置测试可用范围）。

> 长连接模式无需公网 IP、无需内网穿透——MPI 直接连飞书的 WebSocket 端点。面板里也内置了这份指南。

### 17.3 使用与命令

- **私聊**：直接给机器人发文本；
- **群聊**：@机器人（只有 @它的消息会被处理，且需先开通 `im:message.group_at_msg:readonly` 并把机器人拉进群）；
- 绑定的文件夹如果还不是 MPI 项目（没有会话），保存配置时会自动置顶到导航栏，方便查看飞书会话落在哪里；
- 回复先显示「🤔 正在处理」占位，随后随 agent 输出流式刷新，完成后定稿；内容过长会截断（完整结果在 MPI 会话里查看）。
- 命令：`/new` 新建会话（旧会话保留）、`/help` 帮助；
- 同一时间只处理一条消息，处理中再发会收到「还在处理中」提示。

### 17.4 注意

- 渠道仅在 MPI 运行时在线；MPI 未运行（或连接断开）期间发送的消息不会被接收；
- 建议不要在桌面端与飞书同时操作同一个专属会话，以免互相干扰；
- 更换绑定项目后，会在新项目下新建「飞书接入」会话。

## 20. 数据与配置位置

| 内容 | 位置（Windows） | 说明 |
| --- | --- | --- |
| Pi agent 配置 | `%USERPROFILE%\.pi\agent\` | `models.json`、`settings.json`、`auth.json`、扩展/技能/MCP 配置——**与终端 pi 共享**。 |
| 会话文件 | `~/.pi/agent/sessions/`（按项目组织） | JSONL 格式；砖会话修复备份在 `sessions/mpi-repair-backups/`。 |
| 应用配置 | `%APPDATA%\MPI\config.json` | 主题、语言、头像、默认权限等通用设置。 |
| 草稿 | `%APPDATA%\MPI\drafts.json` | 未发送输入，LRU 保留最近 40 份。 |
| 待办任务 | `%APPDATA%\MPI\todos.json` | 按项目记录的待办；智能体写入经 `todos-inbox/` 收件箱去重入库。 |
| 回收站 | `%APPDATA%\MPI\trash\` | 删除的会话文件。 |
| 内置运行时 | `%APPDATA%\MPI\runtime\versions\…` | 首次启动解压；扩展包安装用的内置 npm 也在这里。 |

dev（开发版）与正式安装的配置目录相互独立（`%APPDATA%\MPI Dev` ↔ `%APPDATA%\MPI`），互不干扰；全新 profile 首次启动会继承兄弟 profile 的语言与主题设置。

> API key 属于用户数据：不要把 `auth.json`、会话文件或含密钥的截图提交到仓库或共享出去。

## 21. 常见问题

**模型选择器显示「无可用模型」**
回到「设置 → 模型与提供商」确认已保存；逐项检查 API Key、Base URL（注意 `/v1`）、API 类型、模型 ID，用「测试可用性」定位问题。仍不行时重开一次会话。

**思考等级里没有 `max`（或某档位缺失）**
确认模型卡片打开了「思考」，且 `thinkingLevelMap` 没有把该档位设为隐藏；即使设置里可见，服务商实时返回的能力列表不支持的档位也不会显示。

**新会话没出现在项目下**
会话通常在第一条消息发送后才持久化。先发一条任务，等 Pi 开始回复或完成后再看左侧列表。

**文件 tab 显示的不是当前项目**
文件树跟随**当前会话**的项目文件夹。先切到目标会话，再看「文件」tab。

**生成了内容但预览没更新 / 没有文件产物**
确认聊天中的文件产物路径与当前项目一致；若 Pi 只把 Markdown 贴在聊天里没写文件，继续发送「请把刚才的内容实际写入 docs/result.md」。外部程序修改的文件重新打开预览即可。

**发送失败后输入不见了？**
不会——任何发送失败都会把文本/图片/附件完整恢复到输入框并弹错误提示（见 6.5）。若看到会话里出现无响应的用户气泡，说明是旧版本行为，升级到最新版即可。

**会话突然无法继续、报 provider 拒绝历史**
看输入框上方是否出现红色「一键修复」横幅；有则点击修复（自动备份原文件），没有则把报错信息反馈给维护者。

**升级/重装后任务栏图标还是旧的**
Windows 按路径缓存图标，MPI 已用内容哈希绕开该问题——完整重启一次应用即可看到新图标。

**扩展包安装报 `spawn npm ENOENT` / git 相关错误**
旧版本才可能出现：现在 MPI 内置 npm，未装 Node.js 也能安装；git 源安装需要系统装有 Git（缺失时会有明确提示）。若你手动改过 `settings.json` 的 `npmCommand`，请确认该命令可用。

**dev 版和正式版数据会混吗？**
不会。两者配置目录独立（`MPI Dev` / `MPI`），但共享同一个 `~/.pi/agent`——模型、扩展、会话历史是共用的，这正是设计意图。
