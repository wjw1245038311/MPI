# 知芽记忆系统 · 用户手册

> 本文档只讲**记忆系统**（知芽记忆池）。应用本体的使用手册见「帮助 → 使用手册」。
> 想改记忆模型、想知道某条命令干什么、想知道为什么某条记忆没进池子——查这里。

## 一句话概览

知芽把「值得记的事」沉淀成**文件**（真相源），用**本地向量索引**做语义检索，用**分诊 + 提案 + 审批**把它升级成长期知识。
一切都在本机：模型可选（也可以不接模型），池子不进 git，索引是可重建的派生数据。

**五个能力**：① 自动捕获 ② 手动记录 ③ 语义检索 ④ 归档/遗忘 ⑤ 分诊晋升到知识库。

## 1. 快速开始

| 我想…… | 怎么做 | 需要模型吗 |
|---|---|---|
| 让它自己记住聊出来的经验 | 什么都不用做（一轮对话结束后自动捕获） | **需要**（见 §2） |
| 明确记一条 | `/memory-remember 内容` 或直接说「记住：…」（agent 会调 `memory_note`） | 否 |
| 查一条 | `/memory-search 关键词` 或 `/memory find 关键词` | 否（走本地 embedding） |
| 看池子里有什么 | `/memory-tour`（浏览）/ `/memory-status`（状态总览） | 否 |
| 归档一条（不是删除） | `/memory-forget <id 或正文片段>` | 否 |
| 让它整理成提案 | `/memory-dream` | 正文生成需要模型（不需要则用原文兜底） |
| 审提案 / 批准落地 | `/memory-proposals` → 点一条 → 批准/拒绝 | 否 |

## 2. 记忆模型设置（关键）

**位置**：设置 → 模型与提供商 → 底部「记忆模型」（在摘要模型下方）。

| 选项 | 谁做抽取/打分/正文 | 结果 |
|---|---|---|
| **（不设置：不使用模型）** 默认 | 没人做 | **完全不调模型**。写入/检索/归档照常，但没有自动捕获、没有重要性打分、lesson 正文用原文兜底 —— 与 mem0 的 `infer:false` 形态相同 |
| **跟随主模型** | 当前会话的主模型 | 完整能力；扩展侧由 pi 运行时处理协议与鉴权 |
| **指定 供应商 + 型号** | 你选的那个 | 完整能力；适合用便宜/快的模型跑记忆（例如云端 flash 类） |

**生效时机（重要）**：
- **分诊（dream）**：改完**立即**生效。
- **自动捕获**：扩展在**会话启动时**拿到模型信息 → 改完需要**新开一个会话**（或在没有活动会话时重启应用）。

**选不到的模型怎么办**：供应商不存在、型号不在列表、协议不是 OpenAI 兼容（如 anthropic-messages）、缺 baseUrl —— 都会**退化成「不使用模型」**并在日志里说明原因，不会拿一个连不上的端点让记忆功能整体哑掉。`/memory-status` 里的「记忆模型」一行会显示当前模式与来源。

## 3. 命令一览

| 命令 | 作用 | 备注 |
|---|---|---|
| `/memory` | 总入口：`/memory <内容>` 记一条；`/memory` 浏览；`/memory find <词>` 查找 | |
| `/memory-remember <内容>` | **原文直存**（不改写、不推断） | 不设置模型时也能用，按默认分写入 |
| `/memory-search <词或问题>` | 语义检索（语义端点不可用时自动降级为字面检索，标题会说明） | |
| `/memory-tour [数量]` | 浏览池内条目（倒序，默认 30） | |
| `/memory-status` | 状态总览：条目数 / 索引 / 端点 / 记忆模型 / 提案 / 最近操作回执 | **排障先看这个** |
| `/memory-forget <id 或片段>` | **归档**一条（归档≠删除，可在 archive 目录找回） | 有二次确认 |
| `/memory-dream [--dry]` | 跑一次分诊，产出晋升/归档**提案**（不直接改任何东西） | `--dry` 预览不落盘 |
| `/memory-proposals` | 提案列表（待审批优先）→ **点一条即可批准/拒绝/看正文** | |
| `/memory-approve [id]` | 批准并落地 | **不带参数直接弹列表**，不用敲 id |
| `/memory-reject [id]` | 拒绝（留痕） | 同上，不带参数弹列表 |

> id 只要**前缀或后 8 位**都能用；补全会给出短柄。

**工具（agent 自己调用，你也可以让它调用）**：
- `memory_note` —— 立即记一条（该工具在只读/沙盒模式下也放行：它只写一个候选文件，落不落池由主进程决定）。
- `memory_recall` —— 语义检索（只读）。

## 4. 记忆池与文件位置

```
~/.pi/agent/zhiya/pool/              ← 真相源（文件系统）
├── inbox/2026-09/<ULID>.md          ← 记忆条目（frontmatter + 正文 + 复现记录 + 证据）
├── proposals/<ULID>.md              ← 分诊产出的提案（待审批/已落地）
├── .zvec/                           ← 向量+BM25 索引（可重建，派生数据）
├── .consolidation.json              ← 巩固累加器（150 分阈值）
└── ops.jsonl                        ← 操作回执（归档/批准/分诊的结果都记在这里）
```

- **条目字段**：类型 / 时间指向 / 重要性 / 相关性 / 复现次数 / 项目 / 项目根 / 状态。
- **归档目录**：`AgentSetting/archive/zhiya-pool/`（未配置母版时退回池内 `archived/`）。**归档不是删除**。
- **失败件**：摄入失败的文件落到 `<池>/.failed/`，不会反复重试。

## 5. 分诊、提案与晋升（dream）

**它做什么**：把池子里积压的记忆按规定路线分流，产出**提案**等你审批。

**四个出口**（判定顺序是刻意的：先问过期 → 再问程序性 → 最后按频率）：

| 出口 | 判定 | 落地动作 |
|---|---|---|
| ① 常驻注入 | 程序性规则（如果 X 就做 Y）/ 长期且每次都用到 | 批准后**只给正文**，由你人工合并进画像/约定（不自动改共享文件） |
| ② 项目知识库 | 长期有效、非每次都需、属本项目 | 批准后写入 `<项目>/.alexandria/knowledge/lessons/<Slug>.md`（alexandria 格式），**不自动 commit**，留给你 git diff 审 |
| ③ 当前任务 | 不跨会话但任务仍在进行 | 批准后给正文，由你并入 HANDOFF/changelog/待办 |
| ④ 归档 | 已过时/不成立 | 移入归档目录（可找回） |

**两个触发条件**（管的是不同的事）：
- **规模触发**：累计重要性 ≥ 150 分 → 该跑一次分诊（约 30 条普通记忆）。默认**只记账并提示**，不自动跑；要自动跑需打开配置 `zhiyaDreamAuto`。
- **资格触发**：同一条经验**复现 3 次**（`recurrence ≥ 3`）才算"够格晋升"（认知科学：需反复重放才从海马转入皮层）。

**为什么正文有时是原文**：正文由记忆模型生成；未设置模型、模型不可用、或单次正文预算用尽时，提案正文回退成条目原文，并在理由里标注——**你仍然能审**，设置模型后重跑 `/memory-dream` 即可生成正式 lesson。

## 6. 不接模型时，还剩什么

| 能力 | 不接模型 |
|---|---|
| 显式记录（`/memory-remember`、`memory_note`） | ✅ 可用（按默认分写入） |
| 语义检索（`/memory-search`、`memory_recall`） | ✅ 可用（本地 embedding，不需要 chat 模型） |
| 浏览 / 状态 / 归档 / 删除 | ✅ 可用 |
| 分诊出提案 | ✅ 可用（正文用原文兜底） |
| **自动捕获** | ❌ 停用（需要模型抽取） |
| 重要性打分 | ❌ 停用（用默认分 6） |
| lesson 正文生成 | ❌ 停用（正文=原文） |

**与 mem0 的对照（都不接模型）**：mem0 用 `infer:false` 直存，知芽用原文直存 + 本地索引。实测（30 条真实记忆、10 次检索）知芽写入 35.5ms/条、检索 p50 14.9ms、落地 30/30；mem0 写入 132.8ms/条、检索 p50 107.3ms、落地 20/30。复现命令：`npm run bench:memory-vs-mem0`。

## 7. 排障

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 自动捕获不工作、池子不涨 | 未设置记忆模型（默认档位就是"不使用模型"） | 设置 → 记忆模型 → 选「跟随主模型」或指定模型，然后**新开一个会话** |
| `/memory-status` 显示「端点未启动」 | 当前是终端 pi（没有 MPI 主进程）或 MPI 未运行 | 语义检索降级为字面检索；要用语义检索就在 MPI 里用 |
| 提案正文是原文 | 未设置模型 / 模型不可用 / 本轮正文预算用尽 | 设置记忆模型后重跑 `/memory-dream`（先去拒绝旧提案，否则去重会跳过该条目） |
| 找不到提案 | id 敲错 | 直接 `/memory-approve`（不带参数）从列表里点 |
| 批准后回执显示 ❌ | 目标目录不可写 / 同名 lesson 已存在 / 依据条目已不在池里 | `/memory-status` 看回执详情；同名 lesson 存在时**不会覆盖**，改标题或手动合并 |
| 索引目录变大（几百 MB） | zvec 每次写调用落一个段文件、不自动合并 | 应用启动/退出会自动压缩；也可手动 `npm run memory:optimize` |
| 归档失败 | 池与归档目录**不在同一个卷**（跨盘） | 已内置"复制+校验+删源"回退；若仍失败看回执里的具体错误 |
| 模型返回空、抽取静默无结果 | 本机推理模型把 token 烧在思考上 | 记忆调用已强制关闭思考（`reasoning: off`）；仍在 `/memory-status` 的回执与 dev 日志里能查到原因 |

## 8. 命令行工具（终端里也能用）

```bash
npm run memory:list                      # 列出池内条目
npm run memory:recall -- "查询词"         # 语义检索
npm run memory:add -- "内容"              # 直存一条
npm run memory:reindex                   # 从文件重建索引
npm run memory:optimize                  # 压缩索引（zvec 不自动合并段文件）
npm run memory:dream [-- --dry]          # 跑一次分诊（按设置里的记忆模型解析）
npm run memory:proposals                 # 提案列表
npm run memory:approve -- <id 后 8 位>    # 批准并落地
npm run memory:reject  -- <id 后 8 位>    # 拒绝
npm run bench:memory-vs-mem0             # 与 mem0 的效率对比（不接模型场景）
```

## 9. 设计要点（为什么这么做）

- **文件是真相源，索引是编译产物**：条目是 Markdown（可读、可 diff、可用 Obsidian 编辑），索引随时可重建；索引坏了不影响数据。
- **主进程是唯一写者**：扩展只「提请求」（候选 JSON / 操作请求），落盘、判重、归档、索引更新都在主进程做，避免两个进程同时改池子。
- **三条并发纪律**：读者一律只读句柄并复用、写者短持有+重试、全量重建不原地做（新目录+原子替换）。
- **扩展自包含**：pi 扩展以源码形式写进 userData 加载，不能 import 应用模块，因此它与主进程之间只有**文件契约**（候选 JSON + op 请求 + `ops.jsonl` 回执）。
- **打分两维在写入端，频率×跨度在去向端**：重要性+相关性决定"该不该存"，复现次数决定"够不够格晋升"。
